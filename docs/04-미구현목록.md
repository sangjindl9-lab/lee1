# 미구현·제약 목록 (v0.4.0, 2026-10-31)

화면에서는 아래 기능을 작동하는 것처럼 표시하지 않습니다.

## 아직 만들지 않은 것
| 기능 | 상태·필요한 것 |
|---|---|
| 제조사 전용 드라이버(Hanwha SUNAPI, Hikvision ISAPI, Axis VAPIX, Dahua) | **미구현.** 드라이버 레지스트리에 ‘미지원’으로 표시. 대상 모델·펌웨어 실장비와 공식 문서(Hikvision·Hanwha 는 파트너 계정 필요)를 확보해야 함. 그 전에는 ONVIF·RTSP 로 등록 |
| 카메라 저장영상 회수(Profile G) | 검색·재생 주소 조회까지만. ONVIF Replay(RTSP `Require: onvif-replay`, `Range: clock=`)를 처리하는 전용 수신기가 필요해 미구현 |
| Profile M(메타데이터 스트림) | 이벤트 토픽 중 분석 이벤트만 구분. 메타데이터 스트림 수신·표시는 미구현 |
| 싸움·폭행·투척 등 복합 이상행동 | **미구현.** 행동 인식 모델 필요. 현재는 쓰러짐·뛰기·배회·장시간 정지·군집만 |
| 안전모 전용 학습 모델 | **미포함.** 공개·상용 가능 라이선스의 안전모 모델을 확인하지 못해 색 기반 추정으로 구현. 현장 영상으로 학습한 ONNX 모델을 넣으려면 개발 필요 |
| 안전조끼·안전대(하네스)·마스크 착용 감지 | 미구현 |
| 차량·중장비 검출, 선 넘기(방향), 사람-장비 근접 경고 | 미구현(사람만 검출) |
| GPU(NVIDIA·인텔) 가속 | 미구현. CPU 추론만 |
| 윈도우 설치판 실기 검증 | **미검증.** 리눅스에서 교차 빌드·모의 시험만 함. 윈도우 PC 에서 설치·서비스·관제 프로그램 확인 필요(03-검증결과 ‘윈도우 실기 확인 목록’) |
| 설치 프로그램 코드 서명 | 미적용. 실행 시 ‘알 수 없는 게시자’ SmartScreen 경고가 뜸. 코드 서명 인증서(유료) 필요 |
| 관제 프로그램 전용 기능 | 웹 화면을 창으로 띄우는 방식. 카메라 영상 직접 디코딩(GPU)·조이스틱 PTZ·오디오 양방향은 미구현 |
| 윈도우 자동 업데이트 | 미구현. 새 설치 프로그램을 받아 실행 |
| 윈도우 서버 이중화·NAS 녹화 | 미구현·미검증(서비스 계정이 NetworkService 라 네트워크 공유 폴더 권한 설정 필요) |
| 분석 결과 검색(사람 수·색상 등 메타데이터) | 미구현. 이벤트·스냅샷만 저장 |
| 장애 전환(대체 녹화 서버) | 미구현. 무중단·무손실을 보장하지 않음. 현재는 서비스 자동 재시작·재연결·미확정 구간 복구까지 |
| 양방향 음성(카메라로 말하기) | 미구현 |
| 시청용 코덱 변환(H.265→H.264, AAC→Opus) | 미구현. H.265 는 브라우저 지원 범위만, AAC 음성은 HLS 에서만 재생 |
| 중앙에서 현장 영상 직접 중계 | 미구현. 중앙은 상태만 받고, 영상은 현장 서버 주소(VPN 등)로 접속 |
| NAS 녹화 | 미검증 |
| MJPEG·RTMP·SRT 입력 | 미지원 |
| 2단계 인증(OTP) | 미구현 |

## 구현했지만 제약이 있는 것
| 항목 | 내용 |
|---|---|
| 지능형 분석 정확도 | **실제 현장 영상으로 검증하지 않음.** 합성 장면과 공개 보행자 샘플로 '동작'만 확인. 오탐·미탐 비율 미측정 |
| 불꽃 감지 | 색·흔들림 규칙. 움직이는 주황색 물체·석양·용접·경광등 오탐 가능, 연기 선행 화재는 늦음. 화재감지기 대체 불가 |
| 연기 감지 | 시험 기능. 안개·먼지·조명 변화에 오탐 많음 |
| 안전모 | 색 기반 추정. 사람이 작거나(60px 미만) 뒤돌아 있거나 겹치면 판정 보류·오판 |
| 수위 | 기준 영상 비교. 조명·비·그림자·자재 적치·카메라 흔들림에 영향, 야간 IR 전환 시 별도 기준 필요 |
| 사람 추적 | 1초 간격 검출 + 단순 추적. 사람이 겹치거나 가려지면 번호가 바뀌어 배회·정지 시간이 다시 시작될 수 있음 |
| 쓰러짐 | 박스 가로·세로 비율 기반. 위에서 내려다보는 카메라·쪼그려 앉기에 부정확 |
| 분석 지연 | 감지 후 이벤트까지 지속 시간(기본 3~20초) + 최대 1초 |
| 분석 처리량 | 2코어 기준 사람 분석 카메라 약 2~4대(1초 간격). 넘치면 검출 간격이 자동으로 늘어남(지연) |
| 분석 연결 | 분석용으로 카메라 연결이 1개 추가됨(녹화·실시간 중계와 별도) |
| 윈도우 녹화 서비스 강제 종료 | 리눅스와 달리 남은 FFmpeg 를 정상 종료시킬 수 없어 강제 종료(조각화 MP4 라 마지막 조각까지는 복구) |
| 윈도우 업데이트 재부팅 | 재부팅 중 녹화 끊김(수 분). 사용 시간·정책 설정 필요 |
| 관제 프로그램 새 창 링크 | 웹 화면의 ‘새 창 열기’ 링크는 기본 브라우저로 열림 |
| 음성 권한 | 권한이 없으면 화면에 버튼이 없고 WebRTC 음성 트랙을 요청하지 않음. 단, HLS 재생 시 스트림에 음성이 포함되므로 브라우저 개발자 도구로는 들을 수 있음(서버에서 음성을 제거하는 변환은 미구현) |
| 이벤트 녹화 정밀도 | 10초 구간 단위로 확정 → 실제 녹화는 요청한 전·후 시간보다 최대 10초 더 길 수 있음. 사전 구간은 카메라 키프레임 간격에 영향 받음 |
| 이벤트 녹화 버퍼 | 이벤트 대기 중에도 영상을 받아 최대 2분 임시 저장하므로 카메라 연결·네트워크 부하는 연속 녹화와 같음(디스크 사용만 줄어듦) |
| 끝나지 않는 이벤트 | 장치 오류로 이벤트가 닫히지 않아도 녹화는 시작 후 30분까지만 확정 |
| PTZ 감사로그 | 연속 이동 명령은 사용자·카메라별 1분에 한 번만 기록 |
| 자동 탐색 | 같은 L2 망에서만 동작. 라우터·VPN 너머는 수동 등록 |
| 강제 로그아웃 | 새 연결은 즉시 거부, 이미 열린 WebRTC 세션은 창을 닫거나 재연결할 때 차단(토큰 수명 10분) |
| 녹화 시각 | 서버 시계 기준 ±1~2초 |
| 원본 복사 내보내기 | 직전 키프레임부터 시작(결과에 실제 시작 시각 표시) |
| 공간 기준 정리 | 디스크 전체 여유 기준. 전용 디스크 권장 |
| ONVIF | 연동 구현이며 공식 적합성 인증과 무관 |
