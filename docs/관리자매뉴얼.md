# 관리자 매뉴얼

## 1. 설치
### 온프레미스 (고객사 내부망)
```bash
cp .env.example .env      # JWT_SECRET(무작위 64자), POSTGRES_PASSWORD, PUBLIC_URL 수정
docker compose up -d      # app + PostgreSQL, http://서버:8080
```
- 외부 인터넷 없이 업로드·변환·3D 조회·분해도·MP4 렌더·공유가 동작합니다(환경조명은 내장, 외부 CDN·AI 호출 없음).
- 데이터: Docker 볼륨 `appdata`(/data: 원본·모델·영상), `pgdata`(DB). 백업 = 두 볼륨 + `pg_dump`.
### 클라우드 (Railway 등)
- Dockerfile 배포, `/data` 볼륨 마운트, PostgreSQL 연결 `DATABASE_URL`, `JWT_SECRET`, `PUBLIC_URL`, 헬스체크 `/healthz`.
### 렌더 워커 분리 (GPU·고성능 장비)
- 같은 이미지를 `RUN_WORKER=true` 로 실행, 웹 서버는 `RUN_WORKER=false`. DB 와 `/data` 저장소를 공유해야 합니다(NFS 등).

## 2. 환경변수
| 이름 | 설명 |
| --- | --- |
| DATABASE_URL | PostgreSQL 접속 주소 (슈퍼유저 또는 CREATE ROLE 권한 — 최초 기동 시 `eum_app` 역할·RLS 생성) |
| JWT_SECRET | 세션·공유·렌더 토큰 서명키 (운영 필수) |
| DATA_DIR | 저장 경로 (기본 ./data) |
| PUBLIC_URL | 공유 링크·QR 에 쓰일 외부 주소 |
| RUN_WORKER | 변환·렌더 작업자 실행 (기본 true) |
| INTERNAL_URL | 렌더 워커가 앱에 접속할 주소 (기본 http://127.0.0.1:PORT) |
| CHROMIUM_PATH | 헤드리스 Chromium 경로 (Docker 이미지에는 포함) |
| DWG2DXF_PATH | DWG 변환 엔진 경로 (Docker 이미지 기본 /opt/libredwg/bin/dwg2dxf) |
| MAX_UPLOAD_MB / MAX_RENDER_SECONDS | 업로드 최대 크기(1024) / 영상 최대 길이(120) |

## 3. 계정·권한
- 회원가입 = 새 회사 + 관리자. 같은 회사 사용자 추가는 `POST /api/auth/users` (관리자, 화면 UI 는 4단계).
- 역할: **admin**(전체 + 프로젝트 삭제·사용자·감사로그) / **member**(작성·업로드·렌더·공유·원본 다운로드) / **viewer**(조회만, 원본 다운로드 불가)
- 감사 로그: `GET /api/auth/audit` — 가입·로그인·업로드·모델 생성·원본 다운로드·렌더·공유 생성/폐기/재발급·사용자 추가

## 4. 데이터 격리 점검
- 모든 업무 테이블은 PostgreSQL Row Level Security(FORCE) 로 회사별 분리됩니다. 점검 SQL:
```sql
BEGIN; SET LOCAL ROLE eum_app; SELECT set_config('app.company_id','<회사ID>',true);
SELECT count(*) FROM projects;   -- 해당 회사 행만 보임
ROLLBACK;
```
- 저장소 경로: `/data/storage/companies/<회사ID>/{originals,models,videos}` — 다른 회사 접두사 접근은 코드에서 403.

## 5. 라이선스·화이트라벨 (4단계 예정)
`companies.brand`(로고·프로그램명), `limits`(사용자 수·저장 용량·렌더 분), `features`(기능별 허용) 컬럼은 준비되어 있으나, 라이선스 발급·오프라인 라이선스·한도 강제·관리 화면은 아직 구현되지 않았습니다.
