# 설치·운영 설명서

대상: 카메라에 접근할 수 있는 현장 Linux 서버 또는 미니 PC (Ubuntu 22.04/24.04 권장, x86_64).

## 1. 준비물

| 항목 | 기준 |
|---|---|
| Docker Engine + Compose v2 | `docker compose version` 이 동작해야 함 |
| 시간 동기화 | **NTP 필수**(chrony/systemd-timesyncd). 녹화 시각은 서버 시계 기준 |
| 녹화 디스크 | 운영체제와 분리된 전용 디스크 권장. 용량은 화면의 “저장 용량 산정기” 또는 설계서 10장 공식으로 산정 |
| 네트워크 | 서버 → 카메라: ONVIF(보통 80/443), RTSP(보통 554). 사용자 → 서버: 443/tcp, 8189/udp |
| 인터넷(설치 시) | Docker Hub(이미지), Ubuntu·PyPI·npm 저장소(빌드). 설치 후에는 인터넷 없이 동작 |

> 녹화 디스크를 다른 데이터와 같이 쓰면, 다른 데이터가 공간을 차지할 때 **보관 정책이 오래된 녹화부터 삭제**합니다.
> 전용 디스크를 쓰거나 “최소 여유 공간” 기준을 조정하세요.

## 2. 설치

```bash
# 1) 소스 배치
sudo mkdir -p /opt/web-nvr && sudo tar -xzf web-nvr-0.1.0.tar.gz -C /opt/web-nvr --strip-components=1
cd /opt/web-nvr

# 2) 비밀 파일(마스터 키, DB 비밀번호)과 데이터 폴더 생성 — 최초 1회
sudo bash scripts/init-secrets.sh

# 3) .env 수정 (접속 주소, WebRTC 주소, 녹화 디스크 경로)
sudo nano .env
#   NVR_SITE_ADDRESS=192.168.0.10          ← 브라우저에서 접속할 주소(서버 IP 또는 도메인)
#   NVR_TLS=internal                       ← 사내망. 공인 도메인이면 관리자 이메일
#   NVR_PUBLIC_HOSTS=192.168.0.10          ← WebRTC 후보 주소(LAN IP, 외부 접속이면 공인 IP/도메인도)
#   NVR_RECORDINGS_HOST_PATH=/data/nvr/recordings
#   (경로를 바꿨다면 init-secrets.sh 를 한 번 더 실행해 폴더 소유자를 UID 10001 로 맞춤)

# 4) 빌드·실행
sudo docker compose up -d --build
sudo docker compose ps          # db/api 가 healthy, 나머지 Up 인지 확인
```

### 초기 관리자 생성
비밀번호는 명령줄 인자로 받지 않습니다(셸 기록·프로세스 목록 노출 방지).

```bash
# 대화식 입력
sudo docker compose exec api python -m nvr.cli create-admin --username admin
# 또는 파일/표준입력으로
read -rs P && printf '%s' "$P" | sudo docker compose exec -T api python -m nvr.cli create-admin --username admin --password-file /dev/stdin; unset P
```
- 비밀번호 정책: 10자 이상, 대·소문자·숫자·특수문자 중 3종류 이상, 사용자 ID 포함 금지.
- 첫 로그인 시 비밀번호 변경이 강제됩니다.
- 비밀번호 분실: `docker compose exec api python -m nvr.cli reset-password --username admin` (모든 세션 종료).

### 첫 설정 순서 (웹 화면)
1. `https://<NVR_SITE_ADDRESS>` 접속 → 로그인 → 비밀번호 변경
2. **현장 관리** → 현장 추가 → **허용 네트워크**에 카메라 IP 대역(예: `192.168.10.0/24`) 입력
   (허용망 밖 주소, 루프백·169.254.x.x·멀티캐스트는 연결하지 않습니다)
3. **카메라 관리 → 카메라 등록**: 현장 → ONVIF/RTSP → 주소·인증 → 장치 조회·연결 시험 → 스냅샷 미리보기 → 이름·녹화 → 저장
4. **운영 대시보드**에서 “녹화 중” 확인 → **실시간 관제**에서 영상 확인 → 몇 분 뒤 **녹화 검색·재생**에서 재생 확인

### HTTPS 인증서
- `NVR_TLS=internal`: Caddy 자체 인증 기관이 발급. 브라우저 경고를 없애려면 루트 인증서를 PC에 신뢰 등록합니다.
  ```bash
  sudo docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt ./nvr-root.crt
  ```
- 공인 도메인: `NVR_SITE_ADDRESS=nvr.example.com`, `NVR_TLS=admin@example.com`, 80/443 이 인터넷에서 닿아야 자동 발급됩니다.

## 3. 포트·방화벽

| 방향 | 포트 | 설명 |
|---|---|---|
| 사용자 → 서버 | 443/tcp | 웹·API·WHEP·HLS |
| 사용자 → 서버 | 80/tcp | HTTPS 리다이렉트/인증서 발급(선택) |
| 사용자 → 서버 | 8189/udp | WebRTC 영상. 막히면 HLS 로 자동 전환(지연 수 초) |
| 사용자 → 서버 | 8189/tcp | UDP 차단망용(선택, `NVR_WEBRTC_TCP=true` + compose 포트 주석 해제) |
| 서버 → 카메라 | 80/443, 554 등 | ONVIF·RTSP·스냅샷 |

db(5432)·api(8000)·mediamtx(8888/8889) 는 호스트에 게시하지 않습니다. mediamtx 관리 API 는 꺼져 있습니다.
외부망 시청에 NAT 를 넘는 경우 `NVR_STUN_SERVERS` 또는 TURN 서버(coturn)가 필요할 수 있습니다(설계서 2.1).

Docker 내부망은 `172.31.250.0/24` 입니다. **현장 카메라 대역과 겹치면** `docker-compose.yml` 의 subnet·caddy 고정 IP·
`NVR_DENY_NETWORKS`·`NVR_TRUSTED_PROXIES` 를 함께 바꾸세요.

## 4. 일상 운영

| 작업 | 방법 |
|---|---|
| 상태 확인 | 운영 대시보드(녹화 중/연결 문제/서비스 하트비트/남은 공간), `docker compose ps` |
| 로그 | `docker compose logs -f recorder` (카메라 비밀번호는 로그에 가려서 기록) |
| 카메라 비밀번호 변경 | 카메라 관리 → 수정 → 새 비밀번호. 저장 즉시 녹화가 재인증합니다 |
| 녹화 일시 중지 | 카메라 관리 → 녹화 중지 (등록은 유지) |
| 보관 기간 | 저장장치·보관 화면(기본값), 카메라 수정(카메라별) |
| 증거 보존 | 녹화 검색·재생 → 구간 지정 → 구간 보호(보관 정리에서 제외) |
| 업데이트 | 새 소스로 교체 → `docker compose up -d --build` (DB 마이그레이션은 api 시작 시 자동) |
| 서버 재시작 | `docker compose` 서비스는 `restart: unless-stopped` 로 자동 시작, 녹화는 자동 재개 |

카메라 상태 의미: 녹화 중 / 연결 중 / 재연결 대기(원인 표시: 인증 실패, 연결 거부, 시간 초과, 스트림 없음, 코덱 미지원, 저장공간 부족) / 녹화 꺼짐 / 사용 안 함.
재연결 간격은 2초부터 60초까지 늘어나며, **인증 실패는 카메라 계정 잠김을 막기 위해 60초부터 10분까지** 늘어납니다.

## 5. 백업·복구

| 대상 | 내용 | 방법 |
|---|---|---|
| DB | 사용자·현장·카메라 설정, 녹화 색인, 이벤트, 감사로그 | `scripts/backup.sh` (pg_dump) — 매일 cron 권장 |
| 마스터 키 | 카메라 비밀번호 복호화 키 | `secrets/master.key` — **분실 시 모든 카메라 비밀번호 재입력 필요**, 백업 매체 접근 통제 |
| 녹화 파일 | 영상 | 용량이 크므로 필요한 경우 rsync 등으로 별도(구간 보호 + 내보내기 활용 권장) |

```bash
# 백업 (예: 매일 03:10)
sudo bash scripts/backup.sh /backup/nvr
# cron: 10 3 * * * cd /opt/web-nvr && bash scripts/backup.sh /backup/nvr >> /var/log/nvr-backup.log 2>&1

# 복구 (새 서버 포함)
sudo bash scripts/init-secrets.sh                     # 폴더 생성
sudo docker compose up -d db
sudo bash scripts/restore.sh /backup/nvr/nvr_db_YYYYMMDD_HHMMSS.dump /backup/nvr/master_YYYYMMDD_HHMMSS.key
```
- 녹화 파일만 남고 DB 를 잃은 경우: 빈 DB 로 시작하고 카메라를 **같은 ID 순서로** 다시 등록하면, recorder 가 시작할 때
  파일명(`cam<ID>/연/월/일/<시작ms>_<길이ms>.mp4`)으로 재색인합니다(수동 녹화 구분은 연속으로 복원됨).
- 볼륨 목록: `pgdata`(DB), `mediamtx-config`(자동 생성, 백업 불필요), `caddy-data`(인증서), 호스트 경로의 녹화·내보내기 폴더.

## 6. 문제 해결

| 증상 | 확인 |
|---|---|
| 카메라 “인증 실패” | 카메라 계정·비밀번호, 계정 잠김 여부. ONVIF 조회 화면의 “시계 오차”가 크면 카메라 NTP 설정 |
| “연결 시간 초과/도달 불가” | 서버에서 카메라로 라우팅, 방화벽, VPN. 현장 허용 네트워크에 대역이 있는지 |
| “허용 네트워크 밖의 주소” | 현장 관리에서 허용망 추가(최고관리자) |
| 실시간 영상이 “연결 중”에서 멈춤 | 8189/udp 개방, `NVR_PUBLIC_HOSTS` 에 브라우저가 닿는 주소가 있는지, 그래도 안 되면 HLS 표시 여부 |
| H.265 카메라가 안 보임 | 브라우저 지원 한계. 서브 스트림을 H.264 로 설정(녹화는 H.265 원본 유지) |
| 녹화 누락(빗금) | 이벤트 센터의 “카메라 연결 끊김” 기록과 원인, 저장공간 부족 이벤트 |
| 저장공간 확보 불가 | 보호 구간이 너무 많음 → 보호 해제 또는 디스크 증설 |
| 서비스 “응답 없음” | `docker compose logs recorder worker`, `docker compose restart recorder` |

## 7. 성능 산정
채널 수만으로 판단하지 말고 해상도·FPS·비트레이트·코덱·동시 시청자·변환 여부·디스크 성능을 함께 산정합니다(설계서 10장).
1단계 녹화는 재인코딩이 없어 CPU 부하가 낮고, 부하는 주로 디스크 쓰기(구간 확정 시 약 2배)와 정확 내보내기·워터마크(재인코딩)에서 발생합니다.
대규모(32채널 이상 등) 도입 전에는 실제 카메라로 부하 시험을 하세요 — 이 버전은 다채널 부하 시험을 하지 않았습니다.
