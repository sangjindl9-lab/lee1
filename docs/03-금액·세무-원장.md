# 3. 금액·세무 원장 로직

구현: `src/domain/ledger.ts` · 검증: `test/ledger.test.ts`

> 세무 처리는 플랫폼의 거래 구조(통신판매중개인지 직접 공급인지)에 따라 달라진다. 아래는 명세의 규칙을 구현한 기본값이며, **출시 전에 세무사 검토가 필요하다.** 특히 표시한 세 항목은 검토 결과에 따라 설정을 바꿀 수 있게 해 두었다.

## 계산 순서 (모두 원 단위 정수, 소수 없음)

| 항목 | 식 |
| --- | --- |
| 정산 기준 금액 | 결제액 − 환불 완료액 |
| 수수료 공급가액 | 내림(기준 금액 × 수수료율) |
| 수수료 부가세 | 내림(공급가액 ÷ 10) |
| 결제 비용 | 내림(기준 금액 × 결제 비용률). 부담 주체는 정책으로 지정 |
| 원천징수(개인만) | 소득세 = 10원 미만 절사(기준 × 3%), 지방소득세 = 10원 미만 절사(소득세 × 10%) |
| 실제 지급액 | 기준 금액 − 공급가액 − 부가세 − 판매자 부담 결제 비용 − 원천징수 |

항상 `기준 금액 = 공급가액 + 부가세 + 판매자 부담 결제 비용 + 원천징수 + 지급액` 이 성립하며, `payouts` 테이블의 CHECK 제약이 이를 강제한다.

## 판매자 사업자 유형별 처리

| 유형 | 수수료 증빙 | 원천징수 | 판매자→구매자 세금계산서 |
| --- | --- | --- | --- |
| 법인 | 세금계산서(공급가액 + 부가세) | 없음 | 가능 |
| 일반과세자 | 세금계산서 | 없음 | 가능 |
| 간이과세자 | 세금계산서 | 없음 | `tax_invoice_issuable` 값에 따름(정산 내역에 기록) |
| 개인(비사업자) | 수수료 영수증 | 3.3% 공제, 지급명세서 기초 데이터 생성 | 불가 |

사업자 유형은 주문 시점 값을 주문에 고정한다(`orders.seller_business_type`).

## 예시: 결제 1,000,000원, 수수료 10%, 결제 비용 3.3%(판매자 부담)

| | 법인·일반·간이 | 개인 |
| --- | ---: | ---: |
| 수수료 공급가액 | 100,000 | 100,000 |
| 수수료 부가세 | 10,000 | 10,000 |
| 결제 비용 | 33,000 | 33,000 |
| 원천징수 소득세 | 0 | 25,710 |
| 원천징수 지방소득세 | 0 | 2,570 |
| **실제 지급액** | **857,000** | **828,720** |

## 원장

`ledger_entries` 는 추가만 가능하다. 종류: `payment_in`, `refund_out`, `platform_fee_supply`, `platform_fee_vat`, `pg_fee_seller`, `pg_fee_platform`, `withholding_income_tax`, `withholding_local_tax`, `payout_paid`.

- 결제 확인 시 `payment_in`, 취소 확인 시 `refund_out`, 지급 완료 확인 시 나머지를 한 번에 적는다.
- `ref` 가 유일해서 같은 이벤트를 두 번 처리해도 한 번만 적힌다(`pay:주문`, `refund:환불`, `payout:주문:회차:종류`).
- 주문별 미배분 금액 = 결제 − 환불 − 수수료 − 부가세 − 판매자 부담 결제 비용 − 원천징수 − 지급. 정산이 끝난 주문은 0 이다.
- 통계는 **총 거래액**(결제 − 환불)과 **플랫폼 순수수료 수익**(수수료 공급가액 − 플랫폼 부담 결제 비용)을 따로 낸다. 부가세와 원천세는 예수금이라 수익에 넣지 않는다.

## 수수료 정책

우선순위는 판매자별 > 카테고리별 > 기본이다. 할인 기간은 시작·종료일이 있는 정책으로 표현한다. 주문을 만들 때 적용된 정책을 주문에 복사하므로 이후 정책 변경은 기존 주문에 영향을 주지 않는다(DB 트리거). 판매자에게는 판매 전 같은 계산식으로 예상 정산액을 보여준다.

## 세무사 검토 항목

1. **원천징수 주체와 기준.** 중개 구조라면 소득을 지급하는 쪽이 플랫폼이 아닐 수 있다. 기준 금액은 기본값이 지급액(`net`)이고 수수료 차감 전(`gross`)으로 바꿀 수 있다.
2. **수수료 부가세.** 수수료율을 공급가액 기준(부가세 별도)으로 정했다. 부가세 포함 요율로 운영하려면 계산식 한 곳을 바꾼다.
3. **환불 시 결제 비용.** 남은 결제액 기준으로 계산했다. 취소분의 결제 비용 환급 여부는 사업자 계약으로 확인한다.
4. 세액 절사 단위(10원 미만), 간이과세자 수수료 증빙 방식, 개인 판매자 수수료 증빙(현금영수증 등).

주민등록번호는 저장하지 않는다. 지급명세서 제출에 필요한 식별 정보의 수집·보관 방식은 개인정보 검토와 함께 정한다.
