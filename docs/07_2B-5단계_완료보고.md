## 1. 단계별 구현 기능

### 2단계-B · 회계 핵심

| 기능 | 내용 |
|---|---|
| 복식부기 전표 | 차변=대변을 서버와 DB 제약 둘 다에서 검사. 작성 → 승인 → 취소(미승인은 무효, 승인분은 역분개) |
| 자동 분개 | 검수·지급·세금계산서·기성·수금·하도급 기성·노무비 확정이 각각 규칙(분개규칙 화면에서 계정 변경 가능)에 따라 전표 생성 |
| 계정과목·원가항목 | 건설업 기본 계정표, 공종별 원가항목(재료비·노무비·외주비·경비) |
| 지급결의 | 결재(회계관리자 → 대표이사) 없이는 지급 처리 불가, 같은 결의 이중 지급 차단, 부분 지급 |
| 실행예산 | 현장 × 원가항목 계획, 발주 약정액·실제원가 대비 경고(90% 이상·초과·예산 없음) |
| 현장 손익 | 계약(최초·변경)·매출·수금·원가(실제·약정)·지급·예상 손익 |
| 장부 | 계정별 원장, 거래처 원장, 합계잔액시산표, 재무상태표·손익계산서 |
| 월마감 | 마감한 달은 전표 작성·수정 불가, 마감 취소는 사유와 함께 기록 |
| 구매요청 | 현장 → 구매요청 → 발주서로 전환 |
| 계좌·카드 | 계좌번호 암호화, 원문 조회는 권한·감사로그, 계좌별 출납 |

### 3단계 · 세금계산서·문서 스캔

| 기능 | 내용 |
|---|---|
| 매입 계산서 수집 | 홈택스 엑셀 업로드(미리보기 후 저장) 또는 연동 수집. 승인번호·내용 해시로 **중복 수집 방지** |
| 검수 대사 | 매입 계산서 ↔ 검수 내역 자동 짝맞춤(부분합 탐색), 금액 차이 표시, 차이 처리 후 전표 |
| 매출 계산서 | 작성 → 결재 → 발행. **테스트 모드 발행은 '가상 발행(효력 없음)'으로 표시하고 전표를 만들지 않음**. 운영 발행은 받는 회사 이름을 입력해야 실행 |
| 발행 상태 | 국세청 전송 상태 새로고침, 발행 취소(수정발행 안내) |
| 문서 스캔 | 발주서·거래명세표·세금계산서·영수증 업로드 → 인식(OCR/AI) → **사람이 확인·수정한 뒤에만 등록** |
| 거래처 휴·폐업 조회 | 국세청 상태조회 연동 |
| 외부 연동 설정 | 업체 선택·테스트/운영 모드·키 암호화 저장·연결 테스트·호출 기록·실패 재시도 |

### 4단계 · 공사관리

| 기능 | 내용 |
|---|---|
| 변경계약 | 증감액 결재 후 확정 계약금액 반영, 최초계약 보존, 변경분을 실행예산 초안으로 |
| 기성청구 | 공종별 금회·누적·잔여, 선급금 공제·유보금, 누적 초과 차단(DB 제약), 결재 후 매출 전표, 기성내역서 PDF·엑셀 |
| 수금·미수금 | 기성 수금·선급금·유보금 수령. **매출(기성 승인)과 수금(입금)을 분리**해 미수금으로 관리, 연체 표시 |
| 하도급 | 계약·변경계약·기성·유보금·지급·완료. 기성 결재 후 외주비 전표 |
| 노무비 | 작업자(주민번호·계좌 암호화), 작업일보, 확정(노무비 전표) → 지급결의 |
| 준공정산 | 결재 중 문서가 있으면 정산 불가, 경고 확인 후 정산, 재개 가능 |

| 자금일보 | 계좌별 전일잔액·입금·출금·당일잔액, 그날 입출금 내역, 7일 안 지급·수금 예정 |

## 3. 검증하지 않은 것 (외부 계약이 필요한 부분)

아래는 **코드는 공식 문서 기준으로 작성했지만 실제 업체 서버로 호출해 보지 못한** 부분입니다. 계약 후 테스트 모드에서 먼저 확인해야 합니다. 화면에는 '미연동' 또는 '확인 필요'로 표시됩니다.

| 연동 | 상태 |
|---|---|
| 팝빌 전자세금계산서 발행 | 공식 API 문서 기준 구현, 실제 호출 미검증 (키 없음) |
| 바로빌 발행 | 문서 일부만 확인 — **미검증 표시**. 계약 시 바로빌 테스트 서버에서 항목 검증 필요 |
| CODEF 세금계산서 통합조회 | 제공받은 CODEF 문서(`docs/reference`)로 구현, 실제 호출 미검증 |
| 국세청 사업자 상태조회 | 공공데이터포털 문서 기준, 서비스키 필요 |
| 나라장터 계약정보 | **미검증 표시** — 서비스 주소·응답 항목명이 개편될 수 있어 키를 받은 뒤 실제 조회로 확인 필요. 시연 서버는 '샘플 계약(테스트 전용)' |
| OCR (Claude, CLOVA) | 키 필요. 시연 서버는 '샘플 인식' |
| 은행·카드 자동 수집 | 없음 — 금융 연동 업체 계약 전까지 **엑셀/CSV 업로드**로 같은 업무 처리 |
| 계좌 이체 실행 | 의도적으로 만들지 않음 (지급은 사람이 은행에서 실행 후 ERP에 기록) |

그 밖에:

- Docker 설치용 API 이미지에 PostgreSQL 16 판 `pg_dump` 를 넣도록 바꿨습니다 (화면 백업용). 이 작업 환경에서는 외부 apt 저장소 접근이 막혀 이미지 빌드까지는 확인하지 못했습니다. 설치 시 `docker compose build api` 가 성공하는지 확인하세요. 매일 자동 백업은 기존 `backup` 컨테이너가 계속 맡습니다.
- 세율·원천세 등 세법 값은 '세율 설정'에서 적용일별로 관리하며, 부가세 10% 외의 신고 규칙은 확정하지 않았습니다. 부가세 신고서 작성·전자신고 기능은 없습니다.
- 급여(4대보험·원천징수) 계산은 범위 밖입니다. 노무비는 세전 금액 집계까지입니다.

## 4. 시연 서버

https://ss-erp.onrender.com — 비밀번호 `Demo!2026erp`

| 아이디 | 볼 것 |
|---|---|
| admin (시스템관리자) | 전체 + **관리 > 백업·API 키·웹훅·외부 연동** |
| ceo | 결재함 — 발주서·지급결의·기성·변경계약 결재 |
| acct | 전표·지급결의·세금계산서·**거래내역 대사**·자금일보·보고서 |
| buyer | 자재·발주·검수·문서 스캔 |
| site1 | 배정된 현장만, 작업일보 |
| tax | 외부 세무담당자 — 회계·세금계산서 열람만 |

시연 서버는 컨테이너 안의 내장 DB를 쓰므로 **재배포·재시작하면 데이터가 처음 상태로 돌아갑니다** (시연 데이터 자동 생성, 배포 직후 1~2분 동안은 일부 자료가 아직 없을 수 있음). 실제 업무 자료를 넣지 마세요.
