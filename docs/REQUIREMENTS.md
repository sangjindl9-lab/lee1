# 프로젝트일정표 — 요구사항 명세

원 요구사항: "프로젝트 일정표 만들어줘 보할방식으로"

## 1. 필수 기능

### F1. 프로젝트 관리
- F1-1. 프로젝트를 생성한다. 입력 항목: 이름(필수, 1~100자), 시작일(필수), 종료일(필수), 보할 기준(금액 `amount` / 가중치 `manual`, 기본값 금액), 설명(선택).
- F1-2. 프로젝트 목록을 조회한다. 각 항목에 이름, 기간, 공종 수, 기준일 현재 계획 누계·실적 누계를 표시한다.
- F1-3. 프로젝트 정보를 수정한다. 기간을 줄여 기존 공종이 기간 밖으로 벗어나면 수정을 거부하고 사유를 안내한다.
- F1-4. 프로젝트를 삭제한다. 삭제 전 확인 창을 띄우고, 소속 공종과 실적을 함께 삭제한다.

### F2. 공종(작업) 관리
- F2-1. 공종을 추가한다. 입력 항목: 구분(선택, 예: 토목·건축), 공종명(필수, 1~100자), 금액 또는 가중치(필수, 0보다 큰 수), 시작일, 종료일(둘 다 필수).
- F2-2. 공종을 수정·삭제한다.
- F2-3. 공종의 표시 순서를 위/아래로 바꾼다.
- F2-4. 입력 검증: 종료일은 시작일 이후(같은 날 허용), 공종 기간은 프로젝트 기간 안에 있어야 한다. 위반 시 한국어 오류 메시지를 표시하고 저장하지 않는다.

### F3. 보할 계산
- F3-1. 공종 보할(%) = 해당 공종의 금액(또는 가중치) ÷ 전체 공종 합계 × 100.
- F3-2. 전 공종 보할의 합은 100%이다. 공종이 없으면 합계는 0%로 표시한다.
- F3-3. 공종이 추가·수정·삭제되면 모든 공종의 보할을 다시 계산한다.
- F3-4. 내부 계산은 반올림 없이 수행하고 화면·CSV 표시만 소수 둘째 자리로 반올림한다.

### F4. 계획 공정률 산출
- F4-1. 공종의 보할을 작업 기간의 달력 일수에 균등 배분한다. 기간 p의 공종 계획값 = 보할 × (공종 기간과 기간 p가 겹치는 일수 ÷ 공종 전체 일수). 시작일과 종료일은 모두 일수에 포함한다.
- F4-2. 기간 단위는 월과 주를 지원한다. 월은 달력 월, 주는 월요일~일요일이다. 표의 기간 열은 프로젝트 시작일이 속한 기간부터 종료일이 속한 기간까지이다.
- F4-3. 기간 계획 = 해당 기간의 전 공종 계획값 합. 누계 계획 = 첫 기간부터의 합. 마지막 기간의 누계 계획은 100%이다.

### F5. 실적 입력과 실적 공정률
- F5-1. 공종별로 실적 기록(날짜, 누계 진척률 0~100%)을 등록·수정·삭제한다. 한 공종에 같은 날짜의 기록은 하나만 존재하며, 같은 날짜로 다시 등록하면 값을 덮어쓴다.
- F5-2. 한 공종의 진척률은 날짜순으로 감소할 수 없다. 위반하는 입력은 거부한다.
- F5-3. 특정 날짜의 공종 진척률 = 그 날짜 이전(당일 포함) 가장 최근 기록의 값. 기록이 없으면 0%.
- F5-4. 누계 실적(기간 말) = Σ(공종 보할 × 기간 말 공종 진척률 ÷ 100). 기간 실적 = 해당 기간 누계 실적 − 직전 기간 누계 실적.
- F5-5. 기준일이 속한 기간의 실적은 기준일까지의 값으로 계산하고, 기준일 이후에 시작하는 기간의 실적은 빈 값으로 표시한다.

### F6. 보할 공정표 화면
- F6-1. 행은 공종, 열은 기간인 표를 표시한다. 고정 열: 구분, 공종명, 금액(또는 가중치), 보할(%), 시작일, 종료일, 현재 진척률.
- F6-2. 기간 셀에는 공종의 작업 기간을 나타내는 막대와 해당 기간의 계획값(%)을 표시한다. 작업 기간이 아닌 셀은 비운다.
- F6-3. 표 하단에 기간 계획, 누계 계획, 기간 실적, 누계 실적 4개 행을 표시한다.
- F6-4. 기간 단위(월/주)를 전환할 수 있다.
- F6-5. 기준일을 선택할 수 있다(기본값: 오늘). 기준일이 속한 기간 열을 강조한다.

### F7. 진도 요약과 S-Curve
- F7-1. 요약 카드에 기준일 현재 계획 누계, 실적 누계, 편차(실적 − 계획, %p), 상태를 표시한다. 기준일 현재 계획 누계는 일 단위로 배분한 값이다.
- F7-2. 상태 판정: 편차 ≥ +1%p 이면 "앞섬", 편차 ≤ −1%p 이면 "지연", 그 외 "정상".
- F7-3. 계획 누계 곡선과 실적 누계 곡선을 한 그래프에 그린다. 가로축은 기간, 세로축은 0~100%이다. 실적 곡선은 기준일이 속한 기간까지만 그린다.

### F8. 내보내기
- F8-1. 현재 기간 단위·기준일의 보할 공정표를 CSV 파일로 내려받는다. 엑셀에서 한글이 깨지지 않도록 UTF-8 BOM을 붙인다.
- F8-2. 브라우저 인쇄 시 메뉴·버튼을 숨기고 공정표와 S-Curve만 가로 방향으로 출력되는 인쇄용 스타일을 제공한다.

### F9. 데이터 보존과 실행
- F9-1. 모든 데이터는 로컬 JSON 파일에 저장되며 서버를 재시작해도 유지된다.
- F9-2. `npm install` 후 `npm run build`, `npm start`로 실행하고 브라우저에서 접속한다. `npm test`로 자동 테스트가 실행된다.
- F9-3. 화면의 모든 문구와 오류 메시지는 한국어이다.

## 2. 선택 기능
우선순위가 낮아 이번 개발 작업 목록(TASKS.json)에는 포함하지 않습니다.

- O1. 공종의 기간별 보할을 수동으로 배분(균등 배분 대신 월별 값 직접 입력)
- O2. 대공종–세부공종 2단계 계층과 소계 행
- O3. 엑셀(.xlsx) 내보내기·가져오기
- O4. 휴일·작업일 달력을 반영한 배분
- O5. 프로젝트 복제, 공정표 템플릿
- O6. 분기 단위 보기
- O7. 변경 이력(기준 공정표 대비 변경 공정표 비교)
- O8. 로그인과 사용자별 권한

## 3. 확인 필요 사항과 가정

요구사항이 한 문장이어서 아래 항목은 확인이 필요합니다. 확인 전까지는 명시한 가정으로 개발합니다.

| # | 확인 필요 사항 | 적용한 가정 |
|---|---|---|
| Q1 | "보할방식"의 의미 | 건설·엔지니어링 분야의 보할 공정표(공종별 비중을 기간에 배분해 계획·실적 공정률과 누계를 산출하는 방식)로 해석한다. |
| Q2 | 보할 산정 기준이 금액인지, 물량·공수 등 다른 기준인지 | 금액 기준을 기본값으로 하고, 금액이 없는 프로젝트를 위해 가중치 직접 입력 방식을 함께 제공한다. 프로젝트 단위로 하나를 선택한다. |
| Q3 | 보할을 기간에 배분하는 방법 | 작업 기간의 달력 일수에 균등 배분한다. 수동 배분은 선택 기능(O1)으로 둔다. |
| Q4 | 휴일·주말 제외 여부 | 제외하지 않고 달력 일수를 그대로 사용한다. |
| Q5 | 기간 단위 | 월 단위를 기본으로 하고 주 단위 전환을 제공한다. 주는 월요일에 시작한다. |
| Q6 | 실적 입력 방식(진척률 직접 입력 / 기성 금액 입력) | 공종별 누계 진척률(%)을 날짜와 함께 입력한다. |
| Q7 | 사용자 수와 로그인 필요 여부 | 한 PC에서 한 사람이 쓰는 것으로 보고 로그인을 두지 않는다. |
| Q8 | 관리할 프로젝트 수 | 여러 프로젝트를 등록해 목록에서 선택한다. |
| Q9 | 공종 계층 구조 필요 여부 | 1단계 목록에 "구분" 텍스트 열만 둔다. 계층·소계는 선택 기능(O2). |
| Q10 | 출력 형식 | CSV 내려받기와 브라우저 인쇄를 제공한다. 엑셀 파일은 선택 기능(O3). |
| Q11 | 지연 판정 기준 | 편차 ±1%p를 경계로 앞섬/정상/지연을 판정한다. |
| Q12 | 금액 통화와 단위 | 원 단위 정수 또는 소수를 그대로 입력받고 천 단위 구분 기호로 표시한다. 통화 변환은 없다. |

## 4. 비기능 요구사항
- N1. 외부 서비스·유료 API 없이 로컬에서 동작한다.
- N2. 공종 200개, 기간 60개월 규모의 공정표가 1초 안에 계산·표시된다.
- N3. 최신 크롬·엣지에서 동작한다. 화면 폭 1280px 이상을 기준으로 하며 공정표는 가로 스크롤을 지원한다.
- N4. 비밀정보를 코드에 넣지 않는다. 설정값(포트, 데이터 폴더)은 환경 변수로 받고 `.env.example`에 이름을 적는다.
- N5. 저장 중 오류가 나도 기존 데이터 파일이 손상되지 않는다(임시 파일에 쓴 뒤 교체).
