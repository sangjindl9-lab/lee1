# 노트프로(NotePro) 설계서 — EUM SMART NOTE PRO

> 지시서의 제품명 "EUM SMART NOTE PRO"를 **노트프로**로 바꿔 개발합니다. 패키지 `kr.eumsoft.notepro`.

## 0. 참고 앱(StarNote 1.5.4.1 XAPK) 분석 요약

받은 XAPK를 열어 **구성만** 확인했습니다. 소스코드·화면·아이콘·브랜드 자산은 복제하지 않았습니다.

| 항목 | StarNote에서 확인된 구성 | 노트프로의 선택 |
|---|---|---|
| 제작사·패키지 | Onyx(BOOX), `com.onyx.galaxy.global.note`, minSdk 29 | 자체 패키지, minSdk 26 (구형 기기 포함) |
| 필기 엔진 | 네이티브 라이브러리 다수(획 렌더링·제스처·도형 인식 `libshaperecov2`, `libgesture_core`) | Kotlin 자체 엔진 + 백그라운드 화면 캐시. 지연이 문제되면 2단계에서 `androidx.graphics` 저지연(front-buffer) 렌더러 적용 |
| 손글씨 인식 | 자체 HWR 엔진(`libneo_hwr_jni`, `libSNHTREnginev2`) + ML Kit OCR | 4단계: 교체 가능한 AI 모듈(기기 내 ML Kit Digital Ink + 서버 LLM) |
| 음성 | `sherpa-onnx`, `onnxruntime` (기기 내 음성 인식) | 9장 녹음 기능 단계에서 동일 방식(기기 내) 검토 |
| 저장·동기화 | Room(SQLite), WorkManager, Couchbase LiteCore, Dropbox·Evernote 연동 | SQLite(WAL+FULL) + 작업 기록(op log) 기반 자체 동기화(아래 4장) |
| 문서 | Apache POI(Word·PPT·Excel 변환) | 3단계: 서버 변환(LibreOffice) 우선, 기기 POI는 용량(수십 MB) 때문에 보류 |
| 결제·계정 | Google Play Billing, Huawei, WeChat Pay, Firebase Auth | Play Billing·StoreKit + 자체 계정 서버(이메일·Google·Apple) |
| 앱 보호 | Baidu 앱 보호(난독화·패킹) | R8 난독화 + Play Integrity |

교훈: StarNote도 "필기 엔진·도형 인식은 네이티브, 나머지는 일반 Android" 구조입니다. 지시서 16장의 Flutter 단일 코드베이스 권고와 **펜 지연 품질**이 충돌하므로, 노트프로는 **Android 네이티브(Kotlin)로 1단계를 먼저 완성**하고 핵심 로직(`core/` — 획 코덱·도형 보정·지우개·백업 형식)은 플랫폼 독립 Kotlin으로 분리해 iOS·Windows·웹에서 재사용할 수 있게 했습니다(아래 1장).

**플랫폼 전략**

| 플랫폼 | 방식 | 이유 |
|---|---|---|
| Android 폰·태블릿·전자잉크 | Kotlin 네이티브 (이번 1단계) | 펜 지연·필압·손바닥 무시 품질 |
| iOS·iPadOS | Swift + PencilKit 입력 어댑터, `core/`는 Kotlin Multiplatform으로 공유 | Apple Pencil 지연 최소화 |
| Windows·macOS·Linux | Compose Multiplatform Desktop + Windows Ink 어댑터 | Kotlin UI 재사용 |
| 웹 | Kotlin/Wasm 또는 TypeScript 뷰어 + Pointer Events | 열람·간단 편집 우선 |

`core/` 패키지는 `android.*` 를 전혀 쓰지 않도록 작성했고, 로컬 JVM에서 단위 테스트 13개가 통과했습니다(5장).

- 삭제는 모두 **soft delete**(deleted=1) → 되돌리기·페이지 복구·동기화 모두 같은 방식.
- 화면 표시용 이미지는 DB에 저장하지 않음(렌더 캐시는 메모리만) — 원본 벡터와 분리.

### 2.2 서버(PostgreSQL, 2단계에서 적용)
지시서 17장의 22개 엔터티 전체를 `docs/db/server_001_init.up.sql`(적용)·`.down.sql`(롤백)로 작성했습니다. 모든 표에 PK·FK·created_at·updated_at·deleted_at·인덱스가 있고, 노트 관련 표는 **행 보안(RLS)** 으로 사용자별 격리, 관리자 역할에는 노트 내용 표의 SELECT 권한을 주지 않습니다.

### 2.3 마이그레이션·롤백 절차
`docs/MIGRATIONS.md` 참고. 요약: 기기 DB는 업그레이드 직전 `files/backups/notepro-v{이전}.db` 사본 → 단계별 SQL 적용 → 실패 시 트랜잭션 롤백. 구버전 앱으로 내려가면 DB를 지우지 않고 업데이트를 요구합니다.

## 3. 필기 엔진 설계 (1단계 구현)

**좌표계**: 페이지 포인트(1/72 inch). 화면 = 문서 × 배율 + 이동량. 획은 `(x, y, 필압, 기울기)` 벡터로 저장, 굵기는 그릴 때 펜 모델로 계산 → 확대해도 선명, PDF 내보내기 시 벡터 그대로.

**입력 파이프라인**
1. `MotionEvent` 도구 종류로 펜/지우개 끝/마우스/손가락 분리. `requestUnbufferedDispatch`로 입력 지연 단축, 과거 점(historical)까지 모두 사용.
2. 손바닥 무시: 펜이 닿아 있는 동안 손가락 무시, 펜을 뗀 뒤 350 ms 무시, 접촉 크기(touchMajor) 42 dp 초과 무시, Android 13+ `FLAG_CANCELED`(시스템 손바닥 판정) 시 쓰던 획 취소.
3. 손가락 모드: 자동(펜 감지 전에는 손가락 필기, 감지 후 손가락은 이동만) / 펜 전용 / 손가락 필기.
4. 의도치 않은 확대 방지: 두 손가락 간격이 민감도별 기준(18/36/64 dp) 이상 변해야 확대 시작. 확대 켜기·끄기, **배율 고정**, **페이지 이동 잠금**, 한/두 손가락 스크롤 선택.
5. 손떨림 보정(지수 이동 평균, 최대 0.75로 지연 제한), 중복 점 제거.
6. 도형 보정: 획 끝에서 펜을 550 ms 멈추면 직선(수평·수직·45° 스냅)·원·타원·사각형·삼각형·화살표로 교체(Douglas-Peucker + 타원 오차).

**펜 모델**: 볼펜(필압 영향 작음)·만년필(필압 큼)·연필(기울기로 굵어짐, 반투명)·형광펜(일정 굵기, 겹쳐도 진해지지 않음)·붓(필압 1.3제곱).

**렌더링**: 확정된 획은 전용 스레드에서 화면 크기 비트맵으로 그려 두고(보이는 페이지만), 쓰는 중인 획만 매 프레임 덧그림. 새 획은 캐시 비트맵에 바로 덧그려 전체 재렌더 없이 반영. 확대·스크롤 중에는 기존 비트맵을 변환해 보여 주고 멈춘 뒤 140 ms에 다시 그림. 반투명 펜은 레이어로 그려 겹침 얼룩 방지.

**편집**: 획/부분 지우개(획을 조각으로 분할), 올가미 선택 → 이동·크게·작게·회전·색 변경·삭제·복사·잘라내기·붙여넣기(창 사이 가능), 실행 취소/다시 실행 300단계(지우개 연속 동작은 1단계로 묶음), 두 손가락 탭 = 실행 취소.

## 4. 동기화 프로토콜 (2단계 구현 예정 — 1단계는 기록만 쌓음)

1. **작업 기록**: 모든 변경은 DB 트랜잭션 안에서 `sync_operations`(op_id = UUID, 기기 ID, 대상 ID, 종류)와 함께 커밋 → 데이터와 기록이 어긋나지 않음. *(1단계 구현·테스트 완료)*
2. **Push**: 대기 중 기록을 묶음(최대 500건/1 MB)으로 전송. 서버는 `op_id` 기본키로 **멱등 처리**(같은 작업 재전송 = 무시) → 중복 노트 생성 방지.
3. **Pull**: 기기는 `last_sync_seq` 이후 작업만 받음(증분). WebSocket으로 "새 작업 있음" 알림.
4. **충돌 규칙**(엔터티 rev 기준): 획은 추가 전용·불변 ID라 대부분 충돌 없음. 같은 획을 두 기기가 삭제/수정 → 삭제 우선이 아니라 **양쪽 보존**(진 쪽을 사본으로 남기고 `sync_conflicts` 기록). 노트 제목·페이지 순서는 마지막 쓰기 + 이전 값 버전 보관.
5. **대용량 파일**: SHA-256 내용 주소 + 8 MB 조각 업로드, 실패한 조각만 재시도, 같은 해시는 업로드 생략.
6. **안전 원칙**: 서버 응답과 관계없이 기기 원본은 지우지 않음. 로그아웃·계정 전환 시 미전송 기록이 있으면 경고하고 로컬 데이터 유지. 비회원 노트는 로그인 시 계정에 연결(노트 ID 유지, 작업 기록 일괄 Push).

## 7. 위험 요소와 대응

| 위험 | 영향 | 대응 |
|---|---|---|
