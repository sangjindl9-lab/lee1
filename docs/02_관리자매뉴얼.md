# SS-ERP 관리자 매뉴얼

1단계 기준. 최고관리자 역할을 가진 사람이 읽는 문서입니다.

---

## 1. 설치

### 1.1 서버 준비

| 항목 | 최소 | 권장 (사용자 30명 이상) |
|---|---|---|
| CPU / 메모리 | 2코어 / 4GB | 4코어 / 8GB |
| 디스크 | 50GB SSD | 200GB SSD (첨부파일 증가 고려) |
| OS | Ubuntu 22.04 / 24.04, Rocky 9 등 Docker 가 동작하는 Linux | |
| 네트워크 | 80·443 포트 개방 | 사내 전용이면 VPN 뒤에 두기 |

### 1.2 설치 순서

```bash
git clone <저장소> ss-erp && cd ss-erp/deploy
cp .env.example .env
nano .env
docker compose up -d --build
```

`.env` 에서 반드시 정해야 하는 값

| 이름 | 설명 |
|---|---|
| `ERP_DOMAIN` | 접속 주소. 이 주소의 DNS 가 서버를 가리키면 HTTPS 인증서가 자동 발급됩니다. 사내 IP 로만 쓸 때는 `deploy/Caddyfile` 의 `tls internal` 주석을 해제하세요. |
| `DB_PASSWORD` | `openssl rand -base64 32` 로 만든 값 |
| `APP_ENCRYPTION_KEY` | `openssl rand -hex 32` 로 만든 값. **분실하면 암호화된 계좌번호·2단계 인증을 복구할 수 없습니다.** 금고나 비밀번호 관리기에 따로 보관하세요. |
| `INIT_COMPANY_NAME`, `INIT_COMPANY_BIZNO` | 첫 회사. 사업자등록번호 검증번호가 맞아야 합니다. |
| `INIT_ADMIN_ID`, `INIT_ADMIN_PASSWORD` | 첫 최고관리자. 첫 로그인 때 비밀번호 변경을 요구합니다. |

### 1.3 업데이트

```bash
cd ss-erp && git pull
cd deploy && docker compose up -d --build
```

API 가 시작될 때 새 마이그레이션을 자동 적용합니다. 업데이트 전에 반드시 백업을 하나 더 만들어 두세요 (3.2).

## 2. 사용자와 권한

### 2.1 역할

회사를 만들면 아래 10개 역할이 자동으로 생깁니다. **관리 > 역할·권한** 에서 메뉴별로 조회·등록·수정·삭제·승인·출력·API 권한을 조정할 수 있고, 새 역할도 만들 수 있습니다.

| 역할 | 자료 범위 | 기본 권한 |
|---|---|---|
| 최고관리자 | 회사 전체 | 모든 권한 |
| 대표이사 | 회사 전체 | 조회·출력, 결재 |
| 임원 | 배정 현장만 | 조회·출력, 결재 |
| 회계관리자 | 회사 전체 | 회계·자금·세금계산서 관리, 전표 승인, 마감 |
| 경리담당자 | 회사 전체 | 증빙·전표·지급결의 작성 (승인 불가) |
| 공무담당자 | 배정 현장만 | 계약·실행예산·기성 |
| 구매담당자 | 회사 전체 | 거래처·자재·발주·검수 |
| 현장소장 | 배정 현장만 | 담당 현장 발주요청·지출·노무 |
| 일반직원 | 배정 현장만 | 기본 조회 |
| 외부 세무담당자 | 확정 자료만 | 승인된 회계자료 열람 |

**자료 범위가 "배정 현장만"인 사람은 담당 현장을 지정해야 아무것이라도 보입니다.** 사용자 편집 화면 또는 현장 상세 > 담당자 탭에서 지정합니다.

### 2.2 안전장치

- 본인에게 없는 권한이 들어 있는 역할은 다른 사람에게 줄 수 없습니다 (권한 상승 방지).
- 최고관리자 역할의 사용자·권한 관리 권한은 뺄 수 없고, 최고관리자가 0명이 되는 변경은 거부됩니다.
- 권한 변경은 저장 즉시 모든 사용자에게 적용됩니다.

### 2.3 사용자 등록·관리

**관리 > 사용자 > 사용자 등록**. 저장하면 임시 비밀번호가 한 번만 표시됩니다. 직접 전달하세요 (메신저 단체방 금지). 임시 비밀번호로 로그인하면 바로 새 비밀번호를 정해야 합니다.

| 상황 | 할 일 |
|---|---|
| 비밀번호 분실 | 열쇠 아이콘 → 초기화. 모든 기기에서 로그아웃됩니다. |
| 5회 실패로 잠김 | 자물쇠 아이콘 → 잠금 해제 (15분 지나면 자동 해제) |
| 휴대폰 분실·퇴사 | 로그아웃 아이콘(모든 기기 로그아웃) 후, 편집에서 "이 회사에서 사용 중" 해제 |

퇴사자 계정은 삭제하지 않고 사용 중지합니다. 그 사람이 남긴 기록과 이력을 보존하기 위해서입니다.

---

### 2.4 결재선 (발주서)

**전자결재 > 결재선 설정**. 회사 규정에 따라 **발주서의 마지막 결재는 항상 대표이사**이며 바꿀 수 없습니다. 금액이 큰 발주서에 대표이사 앞 검토 단계(예: 1,000만 원 이상은 회계관리자 검토)를 더할 수 있습니다. 변경은 이후 상신하는 발주서부터 적용됩니다.

**대표이사 역할을 가진 사용자가 한 명도 없으면 발주서를 상신할 수 없습니다.** 사용자 화면에서 대표에게 '대표이사' 역할을 꼭 지정하세요. 공동대표라면 두 사람 모두에게 지정하면 둘 중 한 사람이 결재합니다.

## 3. 백업과 복구

### 3.1 자동 백업

`backup` 컨테이너가 매일 `BACKUP_HOUR` 시(기본 새벽 3시)에 DB 전체와 첨부파일을 `BACKUP_DIR` 에 저장하고, `BACKUP_KEEP_DAYS`(기본 30일)보다 오래된 백업은 지웁니다. 각 백업 폴더에 `SHA256SUMS` 가 있어 손상 여부를 확인할 수 있습니다.

**같은 서버에만 백업이 있으면 서버 고장 때 함께 사라집니다.** `BACKUP_DIR` 을 NAS 마운트 경로로 두거나, 백업 폴더를 매일 외부 저장소로 복사하세요.

### 3.2 수동 백업

```bash
docker compose exec backup sh /scripts/backup.sh
```

### 3.3 복구

```bash
docker compose stop api web
docker compose run --rm -v $(pwd)/backups/20261022-030000:/restore backup sh /scripts/restore.sh
# RESTORE 입력 → DB 복구
docker compose start api web
```

첨부파일은 `storage.tar.gz` 를 `file-storage` 볼륨에 풀어 넣습니다. 복구 후 **관리 > 감사로그 > 무결성 검사**로 기록이 온전한지 확인하세요.

### 3.4 화면에서 백업 (시스템관리자)

**관리 > 백업 > 지금 백업** — 시스템관리자 계정만 보입니다 (백업에 모든 회사 자료가 들어 있기 때문). 백업이 끝나면 `pg_restore --list` 로 파일을 열어 테이블 데이터가 들어 있는지 자동으로 확인하고 SHA-256 을 기록합니다. DB 파일(`.dump`)과 첨부파일(`.tar.gz`)을 각각 내려받을 수 있습니다. Docker 설치에서는 화면 백업이 `app-backups` 볼륨에 최근 10개(`BACKUP_KEEP_MANUAL`)까지 보관되고, 매일 자동 백업은 3.1 의 `backup` 컨테이너가 맡습니다.

화면 백업 파일 복원:

```bash
docker compose stop api web
docker compose cp api:/data/backups/sserp-db-20261022153000.dump ./restore.dump   # 또는 화면에서 받은 파일
docker compose exec -T db pg_restore --clean --if-exists --no-owner -U erp -d erp < restore.dump
docker compose start api web
```

**복구 연습을 분기에 한 번은 해 보세요.** 한 번도 복구해 보지 않은 백업은 있는지 없는지 모르는 백업입니다.

## 4. 감사로그

**관리 > 감사로그** 에 로그인(성공·실패), 등록·수정·삭제(변경 전·후 값), 엑셀 출력, 파일 내려받기, 계좌번호 원문 조회, 권한 변경이 모두 남습니다.

- 기록은 데이터베이스 수준에서 수정·삭제가 막혀 있습니다.
- 각 기록은 앞 기록의 해시를 포함합니다. **무결성 검사** 버튼은 처음부터 다시 계산해, 누가 DB 를 직접 고쳤다면 어느 기록에서 끊겼는지 알려 줍니다.
- 비밀번호·토큰·계좌번호 원문은 기록하지 않습니다.

---

## 5. 라이선스

**관리 > 라이선스**. 설치 직후 30일 평가판(사용자 10명)입니다. 공급사에서 받은 라이선스 문자열을 붙여 넣으면 즉시 적용됩니다. 인터넷 연결 없이 서버에서 서명만으로 확인합니다.

라이선스가 만료되면 **조회와 출력은 계속되고 등록·수정만 막힙니다.** 자료는 절대 잠기거나 지워지지 않습니다.

---

## 6. 세율 설정

**관리 > 세율 설정**. 부가세율은 프로그램에 고정하지 않고 적용 기간별로 관리합니다. 기본값은 부가가치세법 제30조의 10% (1977-07-01~). 법이 바뀌면 새 적용일로 추가하세요. 그 날짜 이후 계약일을 가진 현장부터 새 세율이 적용되고, 기존 현장은 등록 당시 세율을 유지합니다.

## 7. 외부 연동 · API 키 · 웹훅

### 7.1 외부 연동 (관리 > 외부 연동)

세금계산서 발행·홈택스 수집·사업자 상태조회·나라장터·문서 인식 업체를 고르고 키를 넣습니다. 키는 암호화되어 저장되고 화면에는 다시 보이지 않습니다.

- **테스트 모드**: 업체의 테스트 서버로 보내고, 발행한 계산서는 '가상 발행(효력 없음)'으로 표시되며 전표를 만들지 않습니다. 처음에는 반드시 테스트 모드로 '연결 테스트'와 실제 업무 1건을 해 보세요.
- **운영 모드**: 실제 국세청 전송. 매출 계산서 발행 때 받는 회사 이름을 직접 입력해야 실행됩니다.
- 호출 기록(성공·실패·재시도)이 화면 아래에 남습니다. 일시 장애는 자동으로 다시 시도합니다.

준비할 계약·키 목록은 [04_외부연동_준비목록.md](04_외부연동_준비목록.md).

### 7.2 API 키 (관리 > API 키)

외부 프로그램용 키를 발급·폐기합니다. 키 권한은 '발급한 사람의 권한'을 넘을 수 없고, 사용자·권한·연동 같은 관리 기능과 결재는 키로 할 수 없습니다. 원문은 발급 때 한 번만 보입니다. 자세한 사용법은 [08_API_연동가이드.md](08_API_연동가이드.md).

- 키를 발급한 직원이 퇴사하면 계정을 중지하는 순간 그 직원이 만든 키도 모두 막힙니다. 연동이 끊기지 않게 하려면 퇴사 전에 다른 담당자 이름으로 새 키를 발급해 교체하세요.
- 월 1회 '마지막 사용' 을 확인하고 안 쓰는 키는 폐기하세요.

### 7.3 웹훅 (관리 > 웹훅)

발주·결재·지급·세금계산서 같은 업무가 확정되면 등록한 주소로 알립니다. 실패한 발송은 자동 재시도 후 '실패'로 남고 화면에서 다시 보낼 수 있습니다. 운영 환경에서는 https 주소만, 사내망 주소는 등록할 수 없습니다.

### 7.4 API 문서 (Swagger)

`.env` 에서 `SWAGGER_ENABLED=true` 로 바꾸고 `docker compose up -d` 하면 `https://<도메인>/api/docs` 가 열립니다. 외부에 공개된 서버라면 연동 개발 기간에만 켜 두세요.

## 8. 보안 운영 점검표

- [ ] `.env` 파일 권한 `chmod 600`, 서버 관리자 외 접근 불가
- [ ] `APP_ENCRYPTION_KEY` 를 서버 밖 안전한 곳에 별도 보관
- [ ] 회계·자금 권한이 있는 계정은 2단계 인증 사용 (내 계정 > 2단계 인증)
- [ ] 퇴사자 계정 당일 사용 중지
- [ ] 백업이 외부 저장소에도 복사되는지 주 1회 확인
- [ ] 월 1회 감사로그 무결성 검사, 로그인 실패·민감정보 조회 기록 확인
- [ ] 서버 OS·Docker 보안 업데이트 월 1회
- [ ] 데이터베이스 포트(5432)는 외부에 열지 않음 (compose 기본 설정이 내부 전용)
- [ ] 외부 연동이 운영 모드인지 테스트 모드인지 분기 1회 확인, 공동인증서 만료일 확인
- [ ] API 키 '마지막 사용' 확인, 안 쓰는 키 폐기 (월 1회)
- [ ] 화면 백업 파일을 내려받아 서버 밖에 보관 (월 1회 이상)
