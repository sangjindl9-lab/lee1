# 구현 현황과 남은 일

기획서의 원칙대로, 안 된 것을 된 것처럼 적지 않는다.

## 확인된 것 (자동 테스트로 검증)

`DomainTests`가 Unity 없이 실행하는 17개 테스트.

- 재난 시드 재현, 피해도 0~100, 같은 재난·같은 틱 중복 피해 차단
- 주택 1채 = 독립 부재 15개(기초, 골조, 외벽 4, 지붕, 창호 4, 현관문, 전기, 배관, 마감). 지붕만 부서지면 벽·창은 그대로
- 공정 선행조건(조사 → 안전구역 → 잔해 제거 → 지붕 철거 → 지붕 설치 → 검측), 조사 전 계약·검측 전 정산 거부
- 자재: 도착 전 설치 불가, 부족하면 가능한 물량까지만, 재고·예약 음수 없음, 할증 10%(20m2 → 22m2)
- 작업자 2명: 한 작업에 한 명, 적치점에서 자재를 들고 작업점으로 이동, 재난 경보 시 대피·자재 반환, 이후 재개
- 플레이어 직접 작업: 현장에서만, 중단해도 완료량 보존
- 품질 = 자재등급×0.35 + 숙련도×0.35 + 공법×0.2 + 검사×0.1. 75 미만이면 재시공
- 원장: 현금 = 원장 합계, 현금 음수 없음, 준공 정산 1회만
- 저장: 체크섬, 임시 파일 후 교체, 백업 복구, 불러온 뒤 결과 동일
- 전체 플레이(조사 → 계약 → 발주 → 운반 → 시공 → 검측 → 정산)를 12개 시드로 완주

## 작성했지만 실제 Unity에서 확인하지 못한 것

제작 환경에 Unity가 없어서 화면 코드는 한 번도 Unity로 컴파일·실행하지 못했다.
가짜 Unity 정의로 문법·타입만 점검했다. 첫 Actions 빌드에서 오류가 나올 수 있다.

- 3인칭 캐릭터 이동(CharacterController), 추적 카메라와 충돌 당김, 경영 모드 쿼터뷰
- 3D 마을: 주택 6채, 도로, 사무소, 대피소, 작업자, 트럭, 토네이도 (전부 기본 도형)
- 지붕 타일 20장이 파손·철거·설치 진행에 따라 바뀌는 표현
- HUD: 자금·날짜·배속(정지·1·2·5·10)·경보·현장 패널·직원·자재·원장·저장
- 터치 조작(조이스틱, 시점 드래그, 버튼), 한글 글꼴 표시
- Android(IL2CPP, ARM64)·Windows 빌드 스크립트

## 기획서와 다르게 한 것

- 3D 모델: Blender 원본·Prefab·Animator 대신 코드로 만든 기본 도형과 단순 동작. Blender를 쓸 수 없는 환경이었다.
- 렌더링: URP 대신 내장 렌더 파이프라인(Standard 셰이더). 설정 파일 없이 빌드되게 하려는 선택.
- UI: uGUI 대신 IMGUI. Prefab·글꼴 에셋 없이 코드만으로 동작하게 하려는 선택.
- NPC 이동: NavMesh 대신 목표 지점까지 직선 이동. 건물을 통과해 보일 수 있다.
- 차량: 도로 그래프·A* 대신 정해진 경유점 이동. 트럭 1대.
- 프로젝트 구조: Core·Domain·Application·Infrastructure를 `Assets/Game/Sim` 한 어셈블리로 묶음.

## 아직 없는 것

- 홍수·배수, 상가·학교, 정부 입찰, 경쟁 회사 AI, 도시 회복 지표, 대출·파산
- 튜토리얼 연출, 사운드, 다국어(현재 한국어만), 접근성 설정
- 장비 임대·중장비, 창고, 자재 가격 변동
- 클라우드 저장, iOS 빌드, 서명 AAB, 스토어 자료
- 실기기 성능 측정(30/60FPS 목표는 미측정)

## 알려진 결함·위험

- 한글이 Unity 기본 글꼴의 시스템 글꼴 대체로 표시된다. 기기에 따라 깨질 수 있어 실기기 확인이 필요하다.
- 밤(18~08시)에는 작업자가 쉬므로 주택 1채 복구에 게임 시간 약 2일이 걸린다. 10배속으로 2~3분.
- 계약 중 다시 토네이도가 오면 남은 공정을 통째로 다시 짠다(설계변경). 부분 진행된 작업의 진행량 표시는 초기화된다.
