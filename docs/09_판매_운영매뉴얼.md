# SS-ERP 판매·라이선스 운영 매뉴얼 (판매자 전용)

㈜에스에스전력이 SS-ERP를 다른 회사에 **연간 구독**으로 판매할 때의 절차입니다. 고객에게 주지 않습니다.

---

## 1. 전체 구조

| 구성 | 위치 | 역할 |
|---|---|---|
| **라이선스 발급 관리 사이트** | https://ss-license-production.up.railway.app (Railway `ss-license` 프로젝트, 저장소 `license-portal` 브랜치) | 고객 등록, 라이선스 발급·연장·변경·중지, 발급 대장, 만료 예정 고객 |
| **판매자 서명 비밀키** | 발급 사이트 서버 환경변수 + 판매자가 따로 보관한 백업 파일 | 라이선스에 서명. **유출되면 누구나 라이선스를 만들 수 있음** |
| **SS-ERP (고객 서버)** | 호스팅형: Railway에 고객별 프로젝트 / 설치형: 고객사 서버 | 판매자 공개키로 서명을 확인, 사업자등록번호가 맞아야 작동 |

라이선스 한 장에는 **회사명, 사업자등록번호, 사용자 수, 만료일**이 들어 있고 판매자 키로 서명되어 있습니다. 고객이 내용을 고치면 서명이 깨져 인정되지 않습니다.

### 판매 방식

- **호스팅형**: 공급사(우리)가 Railway에 고객 전용 서버를 띄우고 접속 주소만 전달합니다. 고객은 설치할 것이 없습니다. 서버 비용(고객당 월 약 $5~15)은 구독료에 포함해 받습니다.
- **설치형**: 고객사 서버(사내 서버·클라우드)에 Docker로 설치합니다. 서버 관리는 고객 책임입니다.

## 2. 비밀키 보관 (가장 중요)

- 비밀키 백업 파일(`vendor-private.pem`)은 **USB 등 오프라인 저장장치 2곳**에 보관하고, 메일·메신저·클라우드 공유 폴더에 올리지 마세요.
- 발급 사이트 서버를 다시 만들 때 이 파일로 `LICENSE_PRIVATE_KEY` 를 다시 설정합니다 (`base64 -w0 vendor-private.pem` 값).
- 비밀키를 잃어버리면: 새 키를 만들고, SS-ERP의 공개키를 바꾼 새 버전을 배포한 뒤 모든 고객에게 라이선스를 다시 발급해야 합니다.
- 비밀키가 유출됐다고 의심되면 즉시 위와 같이 키를 교체하세요.

## 3. 신규 고객 개통

### 3.1 공통 — 발급 사이트에서

1. **고객 > + 고객 등록**: 회사명, **사업자등록번호**(고객 ERP의 회사 정보와 반드시 같아야 함), 판매 방식, 담당자 연락처.
2. 고객 화면에서 **신규 라이선스 발급**: 사용자 수, 금액(공급가액), 시작일(기본 오늘), 만료일(기본 1년).
3. 고객 화면의 **설치 코드**(예: `SS-7K2Q-9WXM-4HPA`)를 확인합니다.

### 3.2 호스팅형 — Railway에 고객 서버 만들기

Claude에게 *"OO전기 호스팅형 SS-ERP 개통해줘, 사업자번호 000-00-00000, 설치 코드 SS-…"* 라고 요청하면 아래를 대신 진행합니다.

1. Railway에 고객 이름으로 새 프로젝트, PostgreSQL, 앱 서비스(저장소 `lee1`, 브랜치 `ss-erp`, Dockerfile `deploy/render/Dockerfile`), 첨부파일 저장공간(`/data`)을 **싱가포르 리전**에 만듭니다.
2. 환경변수:

| 이름 | 값 |
|---|---|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
| `APP_ENCRYPTION_KEY` | `openssl rand -hex 32` 로 고객마다 새로 (**고객별로 따로 보관**, 잃어버리면 암호화된 계좌번호 복구 불가) |
| `PORT` | `8080` |
| `WEB_ORIGIN` | 고객 접속 주소 (`https://…`) |
| `COOKIE_SECURE`, `TRUST_PROXY` | `true` |
| `FILE_STORAGE_PATH` | `/data/storage` |
| `RAILWAY_RUN_UID` | `0` |
| `INIT_COMPANY_NAME` / `INIT_COMPANY_BIZNO` / `INIT_COMPANY_CODE` | 고객 회사명 / 사업자번호 / 영문 약어 |
| `INIT_ADMIN_ID` / `INIT_ADMIN_PASSWORD` | 고객 최고관리자 계정 (첫 로그인 때 비밀번호 변경 강제) |
| `LICENSE_ACTIVATION_CODE` | 발급 사이트의 설치 코드 |

3. 접속 주소와 최고관리자 계정을 고객에게 전달하고, 발급 사이트 고객 정보의 **ERP 접속 주소**에 적어 둡니다.
4. 고객 서버가 처음 뜨면 15초 안에 발급 사이트에서 라이선스를 받아 옵니다. 발급 사이트 고객 화면의 **ERP 최근 접속**에 시간이 찍히면 연결된 것입니다.

### 3.3 설치형 — 고객사 서버

1. 고객 서버에 소스를 전달합니다 (**`tools/license` 폴더는 빼고**).
2. `deploy/.env.example` → `deploy/.env` 복사 후 값 채우기. `LICENSE_ACTIVATION_CODE` 에 설치 코드를 넣습니다.
3. `docker compose up -d --build` (자세한 순서는 [02_관리자매뉴얼.md](02_관리자매뉴얼.md) 1장).
4. **인터넷이 안 되는 서버**: `.env` 에 `LICENSE_SERVER_URL=` (빈 값)을 넣고, 발급 사이트에서 **파일** 또는 **복사**로 받은 라이선스를 고객 관리자가 **관리 > 라이선스 > 직접 등록**에 붙여 넣습니다. 매년 연장할 때도 같은 방법으로 전달합니다.

## 4. 매년 갱신·변경·중지

| 상황 | 발급 사이트에서 | 고객 서버 반영 |
|---|---|---|
| 1년 연장 | 고객 화면 **1년 연장** (기존 만료일 다음 날부터 1년) + 금액 | 온라인 연결 고객은 6시간 안에 자동, 오프라인은 문자열 전달 |
| 사용자 수 증감 | **사용자 수 변경** (만료일 유지, 추가 금액 입력 가능) | 동일 |
| 연체·해지 | **사용 중지** (만료일을 어제로 재발급) | 다음 확인 때 조회 전용으로 전환. 자료는 남음 |
| 입금 확인 후 재개 | **중지 해제** (중지 전 만료일로 재발급) | 다시 쓰기 가능 |

- **대시보드 > 갱신 연락이 필요한 고객**에 만료 30일 이내 고객이 나옵니다. 매주 한 번 확인해 갱신 견적을 보내세요.
- 고객 ERP에도 만료 30일 전부터 화면 상단에 갱신 안내가 뜹니다.
- 만료돼도 고객 자료는 지워지지 않고 조회·출력은 계속됩니다 (등록·수정만 막힘).
- 오프라인 고객은 '사용 중지'가 자동으로 반영되지 않습니다. 계약서에 해지·연체 조건을 명확히 두세요.

## 5. 자주 있는 문제

| 증상 | 원인·해결 |
|---|---|
| 고객 ERP에서 "이 라이선스는 사업자등록번호 …전용입니다" | 고객 ERP 회사 정보의 사업자번호와 발급 사이트의 번호가 다름. 고객 정보를 확인. 발급 후에는 사이트에서 번호를 못 바꾸므로 새 고객으로 등록 후 재발급 |
| "설치 코드를 찾을 수 없습니다" | 코드 오타이거나 사이트에서 코드를 **다시 만들기** 한 경우. 새 코드를 전달 |
| ERP 최근 접속이 오래됨 | 고객 서버가 꺼졌거나 인터넷 차단. 6시간마다 확인하므로 하루 이상 비면 연락 |
| 발급 사이트 로그인 잠김 | 비밀번호 5회 실패 시 15분 잠김. 비밀번호는 Railway `ss-license` 서비스의 `ADMIN_PASSWORD` |
