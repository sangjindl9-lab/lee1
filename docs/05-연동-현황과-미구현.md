# 5. 실제 연동 여부, 미구현·미지원 항목

## 실제 연동과 샌드박스 구분

| 영역 | 상태 | 설명 |
| --- | --- | --- |
| 회원·권한·세션 | 실제 동작 | scrypt 비밀번호 해시, 로그인 시도 제한, 운영자 추가 인증(비밀번호 재확인) |
| DB | 실제 동작 | PostgreSQL. `DATABASE_URL` 이 없으면 내장 Postgres(PGlite)로 실행 |
| 납품물 보관 | 실제 동작(로컬 디스크) | 파일별 AES-256-GCM 암호화, 주문별 권한, 5분 만료 서명 링크. **S3 호환 저장소 어댑터는 미구현** |
| 비밀키·개인정보 탐지, 압축 파일 방어 | 실제 동작 | zip 내부 텍스트의 일부 패턴만 탐지. 다른 압축 형식과 바이너리는 "검사 불가" |
| 악성 파일 검사 | **미연동** | ClamAV 가 서버에 설치되어 있으면 사용하고, 없으면 "검사 불가"로 표시 |
| 결제·대금 보호·지급 | **샌드박스** | 테스트 결제 시뮬레이터만 있다. 실제 돈이 움직이지 않고 실제 대금 보호가 아니다. 화면 상단과 주문마다 표시한다 |
| PortOne V2 / 토스페이먼츠 | **미연동** | `src/server/providers/sim.ts` 와 같은 인터페이스로 추가해야 한다. 계약과 기능 확인(docs/06)이 먼저다 |
| 세금계산서·현금영수증 발행, 지급명세서 제출 | **미연동** | 기초 데이터(`tax_records`)만 만든다 |
| 이메일·문자 알림 | **미구현** | 사이트 안 알림만 있다 |

## 구현된 범위

- 1단계: 회원, 판매자 등록·심사, 상품 등록·검색·필터, 찜, 구매 전 문의, 파일 버전·보관·검사, 주문 스냅샷, 테스트 결제, 웹훅 검증, 납품, 검수, 구매확정, 분쟁, 환불, 수수료·세무 계산, 정산, 후기, 신고
- 2단계: 의뢰, 견적 비교(금액순), 계약 버전, 단계별 주문·결제·납품·수정 요청·검수, 변경 계약
- 3단계(시뮬레이터 기준): 대금 보호 상태 기록, 외부 지급 보류 결과 기록, 환불·지급의 조회 후 재시도, 대사, 주기 복구 작업
- 4단계: 지식재산권 등록·심사, 비밀유지 동의, 비공개 자료실과 열람 기록, 독점 잠금, 자산 인도 목록, 기업 계정(관리자·구매 담당자·검수 담당자), 구매 승인

## 미구현 항목

| 항목 | 현재 상태 |
| --- | --- |
| 상품 비교 | 없음 |
| 판매 옵션 여러 개 | DB 구조는 있으나 화면은 상품당 옵션 1개 |
| 검색 필터의 "검증 범위" | 없음. 파일별 검사 결과는 상품 화면에 표시 |
| 설치 대행, 유지보수 계약, 업데이트 알림 | 별도 기능 없음. 맞춤 개발 의뢰(유형: 설치·배포, 유지보수)로 대신 |
| 거래 문서 출력 | 없음(브라우저 인쇄만 가능) |
| AI 선택 기능(의뢰서·설명 초안 등) | 없음. 동의 기록 테이블(`ai_consents`)만 준비 |
| 사용자 코드 격리 실행(빌드 확인) | 없음. `files.build_ok` 컬럼만 준비 |
| 운영자 2단계 인증(OTP) | 없음. 비밀번호 재확인만 |
| 분쟁 증빙의 파일 첨부 | 글로만 제출 |
| 대용량 업로드 | 서버 메모리를 거치는 방식. 기본 200MB 제한. S3 직접 업로드로 바꿔야 함 |
| 비밀번호 찾기, 이메일 인증, 회원 탈퇴 | 없음 |
| 이용약관·개인정보처리방침 화면 | 없음 |
| 사후 환불·회수 | 상태 표시와 수동 절차만 |
| Prisma ORM | 쓰지 않음. `schema.prisma` 는 데이터 모델 참조용이고 서버는 SQL을 직접 실행 |

## 기술 스택에서 달라진 점

권장 스택 중 Prisma와 S3는 적용하지 못했다. 개발 환경에서 Prisma 엔진을 내려받을 수 없었고, 최신 Prisma(8)는 구조가 크게 바뀌어 검증 없이 쓰기 어려웠다. 서버는 `pg` 로 SQL을 직접 실행하며, 스키마는 SQL 마이그레이션이 기준이다.
