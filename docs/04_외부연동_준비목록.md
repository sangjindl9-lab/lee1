# 외부 연동 계약·인증 준비 목록

운영 전에 **고객사(또는 판매자)가 직접 계약·신청해야 하는 것**입니다. 프로그램 쪽 연결 기능은 모두 만들어져 있고, 키를 받으면 **관리 > 외부 연동** 에서 업체를 고르고 테스트 모드로 먼저 확인한 뒤 운영 모드로 바꿉니다. 이 키가 없으면 해당 기능은 화면에 "미연동"으로 표시되고, 어떤 경우에도 가짜 결과를 실제처럼 보여 주지 않습니다.

계약 조건·요금·제공 범위는 각 업체 정책에 따라 바뀌므로, 신청 시점에 공식 문서와 영업 담당자에게 확인하세요. 아래는 준비해야 할 항목의 목록이며 각 서비스의 현재 요금이나 세부 사양을 보증하지 않습니다.

| 순서 | 연동 대상 | 쓰이는 기능 | 준비할 것 | 비고 |
|---|---|---|---|---|
| 1 | **팝빌** 또는 **바로빌** (전자세금계산서) | 매출 세금계산서 발행, 국세청 전송상태, 수정발행, 역발행 | 연동회원 가입, 테스트(Sandbox) 계정, 운영 API 키(LinkID·SecretKey 등), 공동인증서(구 공인인증서) 등록, 발행 포인트 충전 | 둘 중 하나 선택. 관리자 설정에서 업체를 고르게 만듭니다 (Provider Adapter) |
| 2 | 홈택스 매입·매출 수집 | 매입 세금계산서 자동 수집, 중복 확인, 발주 대사 | 위 업체의 홈택스 연계(수집) 서비스 신청, 홈택스 부서사용자 또는 인증서 등록 | 발행 API 와 별도 서비스인 경우가 많습니다 |
| 3 | 국세청 사업자등록정보 진위확인·상태조회 | 거래처 휴·폐업 자동 확인 | 공공데이터포털(data.go.kr) 회원가입 → 활용신청 → 서비스키 | 무료, 일일 호출 한도 확인 |
| 4 | 나라장터(조달청) 계약정보 | 관급공사 계약정보 조회 | 공공데이터포털 조달청 관련 OpenAPI 활용신청 → 서비스키 | |
| 5 | OCR / AI 문서인식 | 발주서·거래명세표·영수증 스캔 품목 추출 | 사용할 엔진 결정(국내 OCR 서비스 또는 클라우드 문서인식) 후 API 키. 개인정보·문서 외부 전송 동의 여부 검토 | 교체 가능한 Adapter 로 만들고, 테스트는 샘플 문서로 진행 |
| 6 | 은행·카드 거래내역 | 입출금·법인카드 자동 수집, 미수·미지급 대사 | 금융 데이터 연동 업체(펌뱅킹·스크래핑 중개 등) 계약, 계좌·카드 등록 동의 | 계약 전에는 **엑셀/CSV 업로드**로 같은 업무를 합니다 |
| 7 | (선택) 계좌 이체 실행 | 지급 실행 | 은행 펌뱅킹 계약, 이체 전용 인증 절차 | 지급 요청과 실제 이체는 분리. 별도 승인·법적 인증이 갖춰질 때만 활성화 |
| 8 | (선택) 메일 발송 | 세금계산서·발주서 메일 전송 | 회사 메일 서버(SMTP) 계정 또는 발송 서비스 키 | |

## 프로그램 쪽 준비 상태 (2026-10 기준)

| 연동 | 관리 > 외부 연동 에서 고를 수 있는 업체 | 키 없이 쓰는 방법 |
|---|---|---|
| 세금계산서 발행 | 팝빌, 바로빌(검증 필요 표시), 가상 발행(효력 없음) | 홈택스에서 직접 발행 후 매출 계산서 엑셀 업로드 |
| 홈택스 수집 | CODEF (전자세금계산서 통합조회) | 홈택스 목록 엑셀 업로드 |
| 사업자 상태조회 | 국세청 OpenAPI (공공데이터포털) | 거래처 화면에서 수동 표시 |
| 나라장터 | 조달청 계약정보 OpenAPI (검증 필요 표시), 샘플 계약(테스트 전용) | 현장 직접 등록 |
| 문서 인식 | 내장 PDF 인식(외부 전송 없음), Claude, 네이버 CLOVA, 샘플 인식(테스트 전용) | 내장 PDF 인식 또는 직접 입력 |
| 통장·카드 | (업체 연동 없음) | **자금 > 거래내역 대사** 에서 엑셀/CSV 업로드 |

'검증 필요' 표시가 있는 업체는 공식 문서만으로 만들어 실제 호출로 확인하지 못한 것입니다. 키를 받으면 테스트 모드로 연결 테스트·조회를 해 보고, 응답 항목이 맞지 않으면 공급사에 알려 주세요.

외부 프로그램이 SS-ERP 를 호출하는 쪽(API 키·웹훅)은 [08_API_연동가이드.md](08_API_연동가이드.md) 를 보세요.

## 보관 원칙

- 받은 키·비밀번호는 코드나 메일 본문에 쓰지 말고, 관리 > 외부 연동 화면 또는 서버 `.env` 에만 넣습니다. 저장 시 암호화되고 화면에는 끝 4자리만 보입니다.
- 테스트 키와 운영 키를 반드시 구분해 받으세요. 화면에 운영 모드일 때만 실제 발행 버튼이 열리고, 테스트 모드는 상단 전체에 노란 줄무늬 띠가 표시됩니다.
- 공동인증서는 만료일을 달력에 기록해 두세요. 만료되면 발행·수집이 멈춥니다.
