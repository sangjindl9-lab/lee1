# 6. 출시 전 필요한 계약·정책 검토 항목

## 결제 사업자와 확인·계약할 것

운영 화면의 "결제 사업자 기능" 탭에 근거와 함께 기록한다. 실결제에서는 `digital_goods`, `multi_seller` (맞춤 개발은 `staged_payments` 도)가 "확인됨"이 아니면 결제가 열리지 않는다.

1. 디지털 상품과 개발 용역을 취급할 수 있는가
2. 다수 판매자가 입점하는 구조(지급대행·서브몰)를 지원하는가
3. 지원 결제수단
4. 대금 보호와 정산의 구조(누가 돈을 보관하고 언제 지급하는가)
5. 최대 보류 기간
6. 구매확정·자동확정 방식과 일수
7. 분쟁 시 지급을 멈출 수 있는 범위
8. 결제수단별 부분 환불 조건
9. 단계별(마일스톤) 결제 지원
10. 판매자 확인 절차
11. 이미 지급한 거래의 환불 처리 방식
12. 취소 시 결제 비용 환급 여부

무형 디지털 상품과 장기 용역은 국내 PG의 대금 보호 대상에서 빠지거나 조건이 붙는 경우가 있다. 지원하지 않으면 해당 거래를 "대금 보호 미지원"으로 표시하고 운영해야 한다.

## 법률 검토

- 통신판매중개자로서의 고지 의무와 책임 범위, 통신판매업 신고
- 전자금융거래법상 결제대금예치(에스크로)·전자지급결제대행 해당 여부. 플랫폼이 직접 돈을 보관하지 않고 사업자의 지급대행을 쓰는 구조를 전제로 했다
- 전자상거래법의 청약철회 규정과 디지털 콘텐츠 예외, 그리고 상품별 환불·분쟁 절차 문구
- 이용약관, 판매자 약관, 개인정보처리방침, 분쟁 처리 기준, 자동확정 정책 고지
- 비밀유지 조건 문구와 지식재산권 양도·이용허락 계약서 양식. 지금은 모두 "법률 검토 전 초안"으로 표시된다
- 권리 침해 신고 처리 절차와 반복 침해자 정책

## 세무 검토 (docs/03)

- 개인 판매자 원천징수의 주체와 기준 금액, 지급명세서 제출 방식
- 수수료 부가세 방식(별도인지 포함인지)과 증빙 발행
- 간이과세자, 환불 시 수수료와 결제 비용 처리
- 지급명세서에 필요한 식별 정보의 수집·보관

## 보안·운영

- `SESSION_SECRET`, `FILE_MASTER_KEY`, `JOBS_SECRET` 등 비밀값 생성과 보관, 마스터 키 백업
- HTTPS, 보안 헤더, 요청 속도 제한(현재 로그인만 제한)
- 납품물 저장소를 S3 호환 비공개 버킷으로 전환, 대용량 업로드 방식
- 악성 파일 검사 엔진 연동
- 실제 PostgreSQL 서버에서 환불·지급 동시 실행 부하 테스트
- DB와 저장소 백업·복구 훈련
- 운영자 2단계 인증
- 외부 보안 점검
