# 프로젝트일정표 — 인수 기준

각 항목은 자동 테스트 또는 화면 조작으로 참/거짓을 판정할 수 있는 문장입니다. 번호의 앞부분은 REQUIREMENTS.md의 기능 번호와 대응합니다.

## 기준 예제 데이터

여러 항목에서 아래 "예제 프로젝트"를 사용합니다.

- 프로젝트: 2026-01-01 ~ 2026-03-31, 보할 기준 금액
- 공종 A: 금액 60,000,000, 2026-01-01 ~ 2026-01-31 (31일)
- 공종 B: 금액 40,000,000, 2026-02-01 ~ 2026-03-31 (59일)

기대값(월 단위):

| 항목 | 1월 | 2월 | 3월 |
|---|---|---|---|
| 공종 A 계획 | 60.00 | (빈칸) | (빈칸) |
| 공종 B 계획 | (빈칸) | 18.98 | 21.02 |
| 기간 계획 | 60.00 | 18.98 | 21.02 |
| 누계 계획 | 60.00 | 78.98 | 100.00 |

## AC-F1. 프로젝트 관리

- AC-F1-1. 이름·시작일·종료일을 입력해 저장하면 목록에 해당 프로젝트가 나타나고 `POST /api/projects`가 201과 `id`가 있는 프로젝트를 반환한다.
- AC-F1-2. 이름이 비어 있으면 저장되지 않고 "프로젝트 이름을 입력하세요." 메시지가 표시되며 API는 400 `VALIDATION_ERROR`를 반환한다.
- AC-F1-3. 종료일이 시작일보다 이르면 저장되지 않고 API는 400을 반환한다.
- AC-F1-4. 보할 기준을 선택하지 않으면 `amount`로 저장된다.
- AC-F1-5. 프로젝트 목록의 각 항목에 이름, 기간, 공종 수, 계획 누계, 실적 누계가 표시된다.
- AC-F1-6. 프로젝트 기간을 줄여 기존 공종이 기간을 벗어나게 되면 수정이 400으로 거부되고 저장된 값은 바뀌지 않는다.
- AC-F1-7. 삭제 버튼을 누르면 확인 창이 뜨고, 확인하면 프로젝트가 목록에서 사라지며 이후 `GET /api/projects/:id`는 404를 반환한다.
- AC-F1-8. 프로젝트를 삭제하면 저장 파일에 그 프로젝트의 공종과 실적 기록이 남지 않는다.
- AC-F1-9. 존재하지 않는 프로젝트 id로 조회·수정·삭제하면 404 `NOT_FOUND`를 반환한다.

## AC-F2. 공종 관리

- AC-F2-1. 공종명·금액·시작일·종료일을 입력해 저장하면 공종 표의 마지막 행으로 추가된다.
- AC-F2-2. 금액(가중치)이 0 이하이거나 숫자가 아니면 400으로 거부되고 해당 입력란 아래에 오류 메시지가 표시된다.
- AC-F2-3. 공종 종료일이 시작일보다 이르면 400으로 거부된다. 시작일과 종료일이 같은 공종은 저장된다.
- AC-F2-4. 공종 기간이 프로젝트 기간을 벗어나면 400으로 거부되고 "공종 기간은 프로젝트 기간 안에 있어야 합니다." 메시지가 표시된다.
- AC-F2-5. 공종을 수정하면 표에 수정한 값이 표시되고, 삭제하면 행이 사라지며 그 공종의 실적 기록도 삭제된다.
- AC-F2-6. "아래로"를 누르면 해당 공종이 다음 공종과 자리를 바꾸고, 화면을 새로 고쳐도 바뀐 순서가 유지된다.
- AC-F2-7. 보할 기준이 가중치인 프로젝트에서는 입력란과 표의 열 이름이 "가중치"로 표시된다.

## AC-F3. 보할 계산

- AC-F3-1. 예제 프로젝트에서 공종 A의 보할은 60.00%, 공종 B의 보할은 40.00%로 표시된다.
- AC-F3-2. 금액이 1, 1, 1인 공종 3개의 보할은 각각 33.33%로 표시되고 합계는 100.00%로 표시된다.
- AC-F3-3. 예제 프로젝트에 금액 100,000,000인 공종을 추가하면 공종 A의 보할이 30.00%, 공종 B가 20.00%로 바뀐다.
- AC-F3-4. 공종이 하나도 없는 프로젝트의 보할 합계는 0.00%로 표시되고 공정표 조회가 오류 없이 200을 반환한다.
- AC-F3-5. 가중치 기준 프로젝트에서 가중치 2와 6인 공종의 보할은 25.00%와 75.00%이다.

## AC-F4. 계획 공정률

- AC-F4-1. 예제 프로젝트의 월 단위 기간 계획과 누계 계획이 기준 예제 데이터 표의 값과 소수 둘째 자리까지 일치한다.
- AC-F4-2. 공종이 1개 이상인 모든 프로젝트에서 마지막 기간의 누계 계획은 100.00%이다.
- AC-F4-3. 공종 작업 기간과 겹치지 않는 기간 셀의 계획값은 `null`이며 화면에 빈칸으로 표시된다.
- AC-F4-4. 2026-01-01 ~ 2026-03-31 프로젝트의 월 단위 기간은 "2026년 1월", "2026년 2월", "2026년 3월" 3개이다.
- AC-F4-5. 주 단위에서 모든 기간은 월요일에 시작해 일요일에 끝나고, 첫 기간은 프로젝트 시작일을, 마지막 기간은 프로젝트 종료일을 포함한다.
- AC-F4-6. 2026-01-01(목) ~ 2026-01-14(수), 보할 100%인 공종 1개의 주 단위 기간 계획은 28.57, 50.00, 21.43이다.
- AC-F4-7. 월 단위와 주 단위 각각에서 기간 계획의 합은 100.00%이다.

## AC-F5. 실적

- AC-F5-1. 공종에 날짜와 진척률을 입력해 저장하면 실적 기록 목록에 나타난다.
- AC-F5-2. 같은 공종에 같은 날짜로 다시 저장하면 기록이 추가되지 않고 값이 바뀐다.
- AC-F5-3. 진척률이 0 미만이거나 100 초과이면 400으로 거부된다.
- AC-F5-4. 2026-01-15에 50%가 기록된 공종에 2026-01-20, 40%를 입력하면 400으로 거부되고 "진척률은 이전 기록보다 작을 수 없습니다." 메시지가 표시된다.
- AC-F5-5. 2026-01-15에 50%가 기록된 공종에 2026-01-10, 60%를 입력하면 400으로 거부된다.
- AC-F5-6. 예제 프로젝트에서 공종 A에 2026-01-31 100%, 공종 B에 2026-02-28 50%를 기록하고 기준일을 2026-02-28로 하면 누계 실적은 1월 60.00, 2월 80.00이고 기간 실적은 1월 60.00, 2월 20.00이며 3월의 기간 실적·누계 실적은 빈칸이다.
- AC-F5-7. 위 상태에서 기준일을 2026-01-31로 바꾸면 2월의 실적이 빈칸이 되고 1월 누계 실적은 60.00이다.
- AC-F5-8. 실적 기록이 없는 공종의 현재 진척률은 0%로 표시된다.
- AC-F5-9. 실적 기록을 삭제하면 목록에서 사라지고 누계 실적이 다시 계산된다.

## AC-F6. 보할 공정표 화면

- AC-F6-1. 공정표에 구분, 공종명, 금액(또는 가중치), 보할(%), 시작일, 종료일, 진척률 열과 기간 열이 표시된다.
- AC-F6-2. 공종의 작업 기간에 해당하는 기간 셀에 막대와 계획값이 표시되고 그 외 셀은 비어 있다.
- AC-F6-3. 표 하단에 "기간 계획", "누계 계획", "기간 실적", "누계 실적" 행이 이 순서로 표시된다.
- AC-F6-4. 기간 단위를 "주"로 바꾸면 기간 열이 주 단위로 다시 그려지고 `unit=week`로 조회한 값이 표시된다.
- AC-F6-5. 기준일의 기본값은 오늘이며, 기준일을 바꾸면 요약·실적 행·강조 열이 바뀐 기준일로 갱신된다.
- AC-F6-6. 기준일이 속한 기간 열에 강조 표시가 있다. 기준일이 프로젝트 기간 밖이면 강조되는 열이 없다.
- AC-F6-7. 금액은 천 단위 구분 기호로, 비율은 소수 둘째 자리로 표시된다.
- AC-F6-8. 공종이 없으면 "등록된 공종이 없습니다." 안내가 표시된다.

## AC-F7. 진도 요약과 S-Curve

- AC-F7-1. AC-F5-6의 상태(기준일 2026-02-28)에서 요약 카드는 계획 누계 78.98%, 실적 누계 80.00%, 편차 +1.02%p, 상태 "앞섬"을 표시한다.
- AC-F7-2. 예제 프로젝트에서 실적 기록 없이 기준일을 2026-01-16으로 하면 계획 누계는 30.97%(60 × 16/31), 실적 누계 0.00%, 상태 "지연"이다.
- AC-F7-3. 편차가 −1%p 초과 +1%p 미만이면 상태가 "정상"이다.
- AC-F7-4. S-Curve에 "계획"과 "실적" 범례가 있는 곡선 2개가 그려지고, 계획 곡선의 점 개수는 기간 수와 같다.
- AC-F7-5. 실적 곡선의 점 개수는 실적이 `null`이 아닌 기간 수와 같다.
- AC-F7-6. 계획 곡선의 마지막 점은 세로축 100% 위치에 있다.

## AC-F8. 내보내기

- AC-F8-1. "CSV 내려받기"를 누르면 `.csv` 파일이 내려받아지고, 응답의 `Content-Type`은 `text/csv`이며 `Content-Disposition`은 `attachment`이다.
- AC-F8-2. CSV 본문은 UTF-8 BOM으로 시작하고, 첫 행에 고정 열 이름과 기간 이름이 있으며, 공종 행 수는 공종 수와 같고, 마지막 4행은 기간 계획·누계 계획·기간 실적·누계 실적이다.
- AC-F8-3. 공종명에 쉼표나 큰따옴표가 있어도 CSV 열이 어긋나지 않는다(값이 큰따옴표로 감싸지고 내부 큰따옴표는 두 번 쓰인다).
- AC-F8-4. CSV의 비율 값은 화면과 같은 소수 둘째 자리 값이다.
- AC-F8-5. 인쇄용 스타일에서 머리말, 탭, 버튼 영역은 `display: none`이고 용지 방향은 가로이다.

## AC-F9. 데이터 보존과 실행

- AC-F9-1. 프로젝트·공종·실적을 저장한 뒤 서버를 종료하고 다시 시작하면 같은 데이터가 조회된다.
- AC-F9-2. 데이터 파일이 없는 상태에서 서버를 시작하면 빈 데이터 파일이 만들어지고 프로젝트 목록이 빈 배열로 응답된다.
- AC-F9-3. `DATA_DIR` 환경 변수로 지정한 폴더에 `db.json`이 생성된다.
- AC-F9-4. 저장소 루트에서 `npm install` 후 `npm test`가 실패 없이 종료 코드 0으로 끝난다.
- AC-F9-5. `npm run build`가 종료 코드 0으로 끝나고 `dist/server`와 `dist/client/index.html`이 생성된다.
- AC-F9-6. `npm start` 후 `http://localhost:3000/`에서 화면이 열리고 `GET /api/health`가 200 `{ "ok": true }`를 반환한다.
- AC-F9-7. 화면의 제목, 버튼, 표 머리글, 안내·오류 메시지가 모두 한국어이다.
- AC-F9-8. 저장소의 소스 파일에 비밀번호·API 키가 없고 `.env.example`에는 `PORT`, `DATA_DIR` 이름만 있다.

## AC-N. 비기능

- AC-N-1. 공종 200개, 60개월 프로젝트의 공정표 계산 함수가 1초 안에 결과를 반환한다.
- AC-N-2. 실행 중 외부 네트워크 요청이 발생하지 않는다(화면이 사용하는 글꼴·스크립트는 모두 빌드 산출물에 포함된다).
- AC-N-3. 화면 폭 1280px에서 공정표의 기간 열이 넘치면 가로 스크롤로 볼 수 있고 왼쪽 공종명 열은 고정된다.
